Google Sites 파비콘 추가 및 확인 가이드

Google Sites의 favicon이 브라우저 탭에서 여전히 일반 지구본이나 페이지 아이콘으로 표시된다면, 업로드가 초안에만 반영됐거나 게시된 사이트가 다른 아이콘 URL을 제공했을 가능성이 높습니다. theme XML을 직접 수정하지 않아도 문제를 해결할 수 있습니다.

이 단계별 안내에서는 Google Sites favicon을 추가하고 게시한 뒤, 브라우저에 표시되는 아이콘과 Google Search에서 favicon으로 사용할 수 있는 자격을 각각 확인하는 방법을 다룹니다. 브라우저 확인과 Search 확인은 별개입니다. 한쪽은 정상적으로 작동하더라도 다른 쪽은 recrawl을 기다려야 할 수 있습니다.

아이콘과 사이트 액세스 준비

사이트를 편집하고 게시할 수 있는 브라우저에서 Google Sites를 여세요. 시작하기 전에 로고 마크, 모노그램 또는 심볼을 담은 정사각형 이미지를 준비하세요. 전체 워드마크는 16×16 pixels에서는 일반적으로 읽기 어려워집니다.

  • 액세스: 사이트를 편집하고 게시할 권한이 필요합니다.
  • 원본 이미지: 정사각형 PNG가 가장 간단한 업로드 후보입니다. 실용적으로는 단순한 중앙 마크가 들어간 192×192 PNG를 사용하세요.
  • 게시 URL: 방문자가 favicon을 보게 될 sites.google.com 주소 또는 사용자 지정 도메인입니다.

Google은 Search favicon이 정사각형이고 최소 8×8 pixels여야 한다고 문서화합니다. 또한 48×48보다 큰 크기를 권장합니다. favicon은 표시될 자격이 있을 뿐 실제 표시가 보장되지는 않으며, favicon URL은 안정적으로 유지되어야 합니다. 자세한 내용은 Google의 favicon 문서를 참고하세요.

디자인 원본이 SVG, JPG 또는 다른 형식이라면 업로드하기 전에 정사각형 PNG로 변환하세요. Mzu favicondl로 이 변환을 처리할 수 있습니다. export 전에 디자인을 단순화하면 브라우저 탭에 표시되는 작은 버전에서도 실루엣이 유지됩니다.

사용자 정의 코드 없이 Google Sites favicon 추가

  1. 사이트 설정을 엽니다.

    Google Sites 대시보드를 열고 사이트를 선택한 다음 Edit을 클릭합니다. 편집기 오른쪽 위의 Publish 옆에 있는 More 또는 점 3개 메뉴에서 Site settings를 선택합니다. Favicon 컨트롤을 찾아 파일 선택기를 엽니다.

  2. 이미지를 업로드하고 확인합니다.

    준비해 둔 PNG를 선택합니다. 미리보기 또는 자르기 화면에서 전체 마크가 중앙에 놓이고 잘리지 않는지 확인한 뒤 선택을 저장합니다. 아이콘이 어두운 브라우저 탭에 묻히지 않도록 단색 배경과 충분히 대비가 나도록 합니다.

  3. 업데이트된 사이트를 게시합니다.

    Publish를 클릭하고 사이트 URL을 확인한 다음 업데이트를 게시합니다. Site settings에서 이미지를 저장하는 것만으로는 방문자에게 보이는 사이트가 바뀌지 않으며, 새 버전을 게시해야 적용됩니다.

  4. 게시된 홈페이지를 확인합니다.

    게시된 URL을 편집기 미리보기가 아니라 새 탭에서 엽니다. 브라우저 개발자 도구에서 문서 head에 아이콘 링크가 있는지 확인합니다. 다음 코드를 DevTools 콘솔에서 실행합니다:

    Array.from(document.querySelectorAll('link[rel~=icon]')).map(function (link) {
  return {
    href: link.href,
    type: link.type,
    sizes: link.getAttribute('sizes') || ''
  };
})

    결과에는 favicon URL이 최소 하나 포함되어야 합니다. HTML 표준은 rel='icon'을 아이콘을 위한 외부 리소스 링크로 정의하므로, 링크가 favicon.ico로 끝난다고 가정하지 말고 실제 URL을 확인해야 합니다.

    Network 패널에서 페이지를 새로고침한 뒤 아이콘 요청을 선택합니다. HTML fallback이나 404 응답이 아니라 이미지 응답이 반환되어야 합니다.

  5. 브라우저에서 결과를 확인합니다.

    게시된 페이지를 새로고침한 뒤 탭, 북마크, 바로가기에서 favicon을 확인합니다. 이전 아이콘이 남아 있다면 콘솔에 새 asset URL이 표시되는지 확인한 다음 private window에서 다시 시도합니다. 브라우저는 favicon을 일반 페이지 콘텐츠와 별도로 캐시할 수 있습니다.

  6. Google Search가 다시 크롤링하도록 합니다.

    Google의 Search favicon 요구사항을 사용해 정사각형 형태, 최소 크기, 안정적인 URL, 크롤링 접근 가능 여부를 확인합니다. 게시 후 다시 크롤링되는 데 며칠에서 몇 주까지 걸릴 수 있으므로, Search 결과에 즉시 나타나지 않는다고 해서 업로드가 실패했다고 단정할 수는 없습니다.

    Search 결과에 아이콘이 표시되지 않는 문제를 집중적으로 진단하려면 Google Search favicon 체크리스트를 참고하세요.

Google Sites favicon에서 흔히 겪는 문제

  • 편집 화면 대신 게시된 도메인 확인하기: 편집 화면의 미리보기만 확인하지 말고, 게시된 홈페이지에 favicon이 실제로 반영되었는지 확인하세요.
  • 에셋을 반복해서 변경하기: 파일을 교체할 때마다 새로운 icon URL이 생성될 수 있습니다. Google이 이를 발견한 뒤에는 게시된 URL을 변경하지 마세요.
  • 자세한 로고 사용하기: 16×16 탭에서는 가는 선과 작은 글자가 사라질 수 있습니다. 게시하기 전에 해당 크기에서 테스트해 보세요.
  • 캐시 문제와 Search 반영 지연을 혼동하기: 브라우저에는 새 icon이 표시되는 반면 Google Search에는 이전 icon이 남거나, 그 반대일 수 있습니다. 두 업데이트 경로가 서로 다르기 때문입니다.
  • 경합하는 icon 태그 추가하기: Google Sites의 기본 uploader를 사용할 때는 여러 rel='icon' 후보를 만들 수 있는 불필요한 HTML embed를 피하세요. 문제 해결이 더 어려워집니다.

최종 설정 확인하기

신뢰할 수 있는 순서는 간단합니다. Site settings에서 정사각형 PNG 하나를 업로드하고, 게시한 다음, 실제 홈페이지를 확인하고, 이후 Google Search가 다시 recrawl하도록 두면 됩니다. 다른 no-code 플랫폼도 관리한다면 이 과정을 더 넓은 범위의 no-code website favicon 가이드와 비교해 보세요.

게시된 icon URL은 변경하지 말고, 브랜드 에셋이 바뀔 때는 canonical homepage을 다시 확인하세요. 이렇게 하면 브라우저 사용자, bookmark client, Google crawler가 모두 하나의 일관된 source를 참조할 수 있습니다.

ASP.NET Core favicon 설정 가이드

ASP.NET Core 앱에서 브라우저 탭이 비어 보이거나 브랜드 대신 기본 아이콘이 표시된다면, 보통 렌더링되는 <head>에 아이콘 연결이 없거나 정적 콘텐츠로 노출된 폴더 밖에 파일이 저장되어 있기 때문입니다. ASP.NET Core favicon을 설정하려면 두 가지가 필요합니다. wwwroot 아래에 있는 아이콘 파일과 공유 레이아웃의 link 선언입니다.

이 구분을 중요하게 봐야 합니다. favicon.ico를 프로젝트 루트에 넣는다고 wwwroot 아래에 배치되는 것은 아니며, wwwroot에 파일을 추가한다고 모든 페이지에 자동으로 적용되는 것도 아닙니다. 아래 단계는 일반적인 공유 레이아웃을 사용하는 MVC 및 Razor Pages 앱을 기준으로 합니다.

사전 조건

  • 공유 _Layout.cshtml 파일을 통해 HTML을 렌더링하는 ASP.NET Core 앱
  • 레이아웃과 wwwroot 폴더를 수정할 수 있는 권한
  • favicon 형식으로 변환할 수 있는 정사각형 로고 또는 PNG

앱에서 public, account, admin 레이아웃을 각각 사용한다면 각 레이아웃에 markup 단계를 반복해서 적용해야 합니다. API 전용 앱에는 설정할 페이지 head가 없으므로, 대신 landing page 또는 documentation host에 favicon을 추가하십시오.

ASP.NET Core favicon 추가 단계

  1. 작은 아이콘 세트 준비

    다음 폴더 구조를 만듭니다.

    wwwroot/
  favicon.ico
  icons/
    favicon.svg
    favicon-32x32.png
    apple-touch-icon.png

    16, 32, 48픽셀 이미지를 담은 ICO, 32픽셀 PNG, 간단한 SVG를 사용합니다. 사용자가 사이트를 홈 화면에 저장할 수 있다면 180픽셀 크기의 Apple touch icon도 추가합니다. 소스가 로고 또는 PNG라면 Mzu favicondl을 사용해 원본 파일을 변경하지 않고 ICO, PNG, SVG 버전을 만들 수 있습니다.

  2. 정적 파일 제공 여부 확인

    ASP.NET Core는 static-file middleware를 통해 wwwroot에 있는 파일을 제공합니다. 앱에서 이미 해당 폴더의 CSS나 이미지를 불러오고 있다면 이 단계는 이미 처리되었을 가능성이 높습니다. 그렇지 않으면 파이프라인에 다음이 포함되어 있는지 확인합니다.

    var app = builder.Build();

app.UseStaticFiles();

// Keep your existing routing and endpoint registrations below.

    이 호출은 한 번만 추가합니다. middleware 항목이 이미 있다면 두 번 등록하지 마세요.

  3. 공유 head에 링크 추가

    MVC라면 Views/Shared/_Layout.cshtml를, Razor Pages라면 Pages/Shared/_Layout.cshtml를 엽니다. 다음 요소들을 stylesheet 링크 옆에 배치하고 &lt;head&gt; 안에 넣습니다.

    &lt;link rel='icon' href='~/favicon.ico' sizes='16x16 32x32 48x48'&gt;
&lt;link rel='icon' href='~/icons/favicon-32x32.png' type='image/png' sizes='32x32'&gt;
&lt;link rel='icon' href='~/icons/favicon.svg' type='image/svg+xml' sizes='any'&gt;
&lt;link rel='apple-touch-icon' href='~/icons/apple-touch-icon.png' sizes='180x180'&gt;

    rel='icon' 형식은 HTML link-type 문서의 정의에 따라 외부 아이콘 리소스를 식별합니다. Razor의 ~/ 경로를 사용하면 앱이 하위 경로 아래에 호스팅될 때 URL이 올바르게 유지됩니다. layout에 &lt;head&gt;가 없다면 링크를 삽입하기 전에 head를 추가합니다.

  4. 루트 ICO fallback 유지

    wwwroot/favicon.ico에 있는 파일은 /favicon.ico에서 제공됩니다. 호환성을 위해 해당 파일과 명시적인 ICO 링크를 유지합니다. 그러면 페이지 템플릿이 불완전하더라도 브라우저의 통상적인 루트 경로 요청에 유효한 응답이 돌아갑니다.

  5. 앱 실행 후 각 응답 확인

    dotnet run으로 사이트를 시작하고 로컬 URL에 접속한 다음 브라우저 개발자 도구를 엽니다. Network 패널을 선택하고 favicon으로 필터링한 뒤 페이지를 새로고침합니다. 표시되는 아이콘 요청은 404 응답이 아니라 성공적으로 반환되어야 하며, content type은 이미지여야 합니다. View Source로 반환된 HTML에 link 요소 네 개가 포함되어 있는지 확인한 다음 브라우저 탭에 의도한 마크가 표시되는지 점검합니다.

  6. 게시된 사이트 검증

    앱을 배포하고 live page source를 확인한 뒤 Network 검사를 반복합니다. 아이콘이 로컬에서는 동작하지만 production에서는 동작하지 않는다면 생성된 href 값을 배포된 URL과 비교하고 아이콘 파일이 게시 출력에 포함되어 있는지 확인합니다. 이전 아이콘이 계속 보인다면 CDN, service worker 또는 browser favicon cache를 조사하기 전에 private window에서 먼저 확인해 보세요.

흔한 함정

  • 본문 안의 링크: 아이콘 선언은 문서 head에 넣습니다. 또한 페이지에서 해당 레이아웃을 사용하지 않으면 레이아웃 조각이 렌더링되지 않을 수도 있습니다.
  • wwwroot 밖의 파일: 프로젝트 루트에 있는 파일은 static-file middleware가 서비스하지 않습니다.
  • root 경로를 직접 지정: 앱이 path prefix 아래에서 실행될 수 있는 경우 Razor layouts에서는 ~/를 사용합니다.
  • middleware 누락: Network panel에서 모든 아이콘이 404를 반환한다면 먼저 app.UseStaticFiles()를 확인합니다.
  • 오래된 출력물: 업데이트된 wwwroot 콘텐츠를 다시 배포하고 캐싱도 고려합니다.
  • 손상된 원본 아트워크: 잘못된 SVG markup를 제거하고, 모든 ICO 파일에 선언된 레이어가 실제로 포함되어 있는지 확인합니다.

markup과 응답이 모두 정상인데도 탭에 잘못된 아이콘이 계속 표시된다면, 더 포괄적인 favicon 문제 해결 체크리스트를 따라가 보세요. HTML만으로 진행하는 기본 과정은 웹사이트에 favicon 추가하는 방법에서 확인하세요.

깔끔한 아이콘 구성으로 마무리하기

파일이 wwwroot 아래에 있고 static-file middleware가 작동하며, 공유 레이아웃이 ICO, PNG, SVG 후보를 선언했다면 ASP.NET Core favicon 설정은 준비된 것입니다. root에 있는 favicon.ico를 유지하고, 배포된 응답을 확인한 뒤에야 탭 아이콘 설정이 완성되었다고 판단하세요.

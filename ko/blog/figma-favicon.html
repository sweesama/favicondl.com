Figma favicon 내보내기 및 웹사이트에 추가하기

브랜드를 Figma에서 설계했는데도 브라우저 탭에 일반적인 페이지 아이콘이 계속 보인다면, 대개 내보내기와 게시 단계가 빠져 있는 것입니다. Figma favicon은 정사각형 프레임에서 시작하지만, 브라우저가 요구하는 것은 완성된 파일과 HTML 링크입니다. 이 작업 흐름을 따라가면 Figma canvas에서 사이트에 배포된 아이콘까지 만들 수 있습니다.

준비 사항

  • Figma 편집기와 브랜드 에셋이 들어 있는 파일에 대한 접근 권한.
  • 작은 크기에 맞게 조정할 수 있는 로고, 심볼 또는 기타 마크.
  • 내보낸 PNG 또는 SVG 파일.
  • 사이트의 static assets를 게시하는 폴더 또는 build pipeline에 대한 접근 권한.

Figma favicon 만들기 및 내보내기

  1. 1. 정사각형 master frame 만들기

    Figma의 Frame 도구로 canvas를 클릭한 뒤 Width와 Height를 모두 512로 설정합니다. frame 이름을 Favicon / Master로 변경하고, 단순화한 brand mark을 작은 여백을 두고 배치하세요. tab 크기에서 바로 시작하는 것 나중에 축소하는 편이 디자인을 더 잘 제어할 수 있습니다.

    wordmark를 사용한다면 전체 가로 로고를 축소하는 대신 첫 글자나 심볼만 복제합니다. 높은 배율로 확대해 가장 작은 counters와 stroke joins를 확인하세요. Figma의 pixel grid를 활용하면 16 × 16 px에서도 간격이 유지되는지 알 수 있으므로, export하기 전에 세밀한 요소를 단순화합니다.

  2. 2. artwork를 component로 정리하기

    완성된 frame으로 component를 만든 다음, 레이어를 Icon/Background와 Icon/Mark처럼 명확한 이름으로 group화합니다. light 버전과 dark 버전이 필요하다면 geometry가 동일한 component variants를 만드세요. 일관되게 관리되는 variants를 export하면 작은 수동 편집이 서로 다른 favicon을 만드는 일을 막을 수 있습니다.

  3. 3. PNG와 SVG master export하기

    master frame을 선택하고 Figma의 오른쪽 sidebar에서 Export를 여세요. PNG export를 추가하고 1×로 유지해 512 px 이미지를 export합니다. SVG export도 추가하세요. PNG는 raster source를 제공하는 반면, SVG는 이를 지원하는 브라우저에서 vector geometry를 보존합니다.

    export한 뒤 별도의 viewer에서 PNG를 열어 canvas가 정사각형인지, mark가 중앙에 있는지, background가 의도한 색인지 확인합니다. 변환 전에 실수로 선택한 group이나 원치 않는 transparent margin이 있는지 이를 통해 잡아낼 수 있습니다.

  4. 4. 작은 size 생성하기

    Mzu favicondl을 사용해 PNG 또는 SVG를 여러 size의 favicon.ico와 사이트에 필요한 PNG size로 변환합니다. 확장자만 .ico로 바꾼 PNG를 업로드하는 대신 원본 SVG를 유지하세요. favicon size guide에서 16, 32, 48, 180, 192, 512 px 파일이 각각 어디에 사용되는지 설명을 확인할 수 있습니다.

  5. 5. HTML에 icon link 추가하기

    다음 코드를 문서의 <head>에 붙여 넣으세요. asset이 다른 위치에 있다면 path를 조정합니다.

    <link rel='icon' href='/favicon.ico' sizes='any'>
<link rel='icon' href='/favicon.svg' type='image/svg+xml'>
<link rel='icon' href='/favicon-32.png' type='image/png' sizes='32x32'>
<link rel='icon' href='/favicon-192.png' type='image/png' sizes='192x192'>
<link rel='apple-touch-icon' href='/apple-touch-icon.png' sizes='180x180'>

    HTML Living Standard는 icon resource를 선언하기 위한 rel='icon' link를 정의합니다. 각 path가 서버에 게시된 filename과 일치하도록 관리하세요.

  6. 6. 일치하는 path에 파일 게시하기

    파일을 사이트가 실제로 제공하는 디렉터리에 넣습니다. root deployment은 다음 구조를 사용할 수 있습니다.

    /
├── favicon.ico
├── favicon.svg
├── favicon-32.png
├── favicon-192.png
└── apple-touch-icon.png

    bundled project에서는 해당 위치가 public/, static/ 또는 설정된 다른 asset 폴더일 수 있습니다. deployment pipeline이 해당 폴더를 자동으로 처리하지 않는다면 build output에도 파일을 복사하세요.

  7. 7. live response 확인하기

    static preview를 확인하려면 index.html이 있는 폴더에서 python3 -m http.server 8000을 실행한 뒤 http://localhost:8000을 여세요. 이 방법은 서버가 사용할 것과 동일한 HTTP path를 확인하면서 file URL 방식의 동작을 피할 수 있습니다.

    DevTools를 열고 Network을 선택한 다음 favicon으로 필터링하세요. 요청된 각 파일이 정상 응답을 반환하고 image로 열리는지 확인합니다. cached view 하나만 믿지 말고 browser tab, bookmark, 새로 연 tab에서 각각 확인하세요. icon이 없거나 오래된 파일이 보이면 디자인을 변경하기 전에 favicon troubleshooting checklist를 확인하세요.

흔한 실수

  • 로고 전체를 export하는 것. favicon에는 한눈에 알아볼 수 있는 mark 하나가 필요합니다. wordmark나 가로형 로고 전체를 사용하면 안 됩니다.
  • 세부 묘사를 과하게 사용하는 것. 가는 선, 아주 작은 글자, low-contrast 색상은 16 × 16 pixels에서는 사라집니다. raster export를 sharpening하는 대신 master를 단순화해야 합니다.
  • format과 이름을 혼동하는 것. 확장자가 .ico인 PNG는 여전히 PNG입니다. 파일명만 바꾸는 대신 ICO container를 생성해야 합니다.
  • 잘못된 folder에 publish하는 것. source directory에 있는 파일은 deployed site에 copy되지 않을 수도 있습니다. 최종 public URL에서 확인하세요.
  • SVG에만 의존하는 것. SVG를 render할 수 없는 environment를 위해 ICO 또는 PNG fallback을 유지해야 합니다.
  • mobile icon을 빠뜨리는 것. Apple touch icon은 별도의 asset이며, desktop tab image를 export해도 생성되지 않습니다.

결론

이제 Figma file에는 production까지 이어지는 명확한 경로가 있습니다. square component를 설계하고 PNG와 SVG master를 export한 다음, fallback format을 생성해 publish하고 page head에 선언하세요. source component는 edit 가능한 상태로 유지해야 향후 brand 변경을 하나의 관리된 asset에서 시작할 수 있습니다.

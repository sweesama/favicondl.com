GoDaddy Website Builder favicon 설정 가이드

GoDaddy 사이트가 브라우저 탭에 계속 기본 아이콘을 표시한다면, 교체한 아이콘이 미리보기에만 적용되어 있거나 브라우저가 기존 아이콘을 계속 사용하고 있을 수 있습니다. GoDaddy Website Builder favicon은 페이지 섹션 안에 배치하는 이미지가 아니라 사이트 전체에 적용되는 브라우저 아이콘입니다. 편집기에서 favicon을 업로드하고 사이트를 게시한 다음, 실제 라이브 HTML이 제공하는 favicon을 확인하세요.

사전 준비 사항

GoDaddy 사이트를 편집하고 게시할 수 있는 권한과 정사각형 원본 이미지가 필요합니다. PNG는 업로드에 적합한 형식이며, 512×512 px 원본을 사용하면 내보내기 전에 디자인을 간소화할 여유가 생깁니다. 가는 선과 세밀한 텍스트는 작은 크기에서는 사라지기 쉬우므로 16×16 px에서도 심볼을 식별할 수 있게 유지하세요.

  • GoDaddy 로그인 정보와 Website Builder 사이트 접근 권한
  • 배경이 선명한 정사각형 PNG 또는 SVG 원본 이미지
  • 실제 운영 중인 도메인 URL과 Developer Tools를 지원하는 브라우저

Mzu favicondl로 최종 PNG, ICO, SVG 파일을 준비할 수 있습니다. 기본 업로더를 이용하는 방법이 가장 간단하며, 추가 형식은 수동 대체 방법이 필요할 때만 유용합니다.

GoDaddy Website Builder Favicon 단계별 추가 방법

1. Website Builder에서 사이트 열기

GoDaddy에 로그인하고 Websites and Shop을 연 다음, Website Builder 사이트와 연결된 도메인을 선택하세요. Edit Website를 선택해 편집기로 들어갑니다. 이미 편집기가 열려 있다면 다음 단계로 바로 진행하세요.

2. favicon 설정 열기

편집기의 사이트 전체 설정 패널을 열고 Favicon을 찾으세요. 현재 편집기 레이아웃에 따라 이 옵션은 Settings 아래에 있거나 Website icon으로 표시될 수 있습니다. 섹션 내부의 이미지 블록이나 일반 로고 입력란이 아니라 사이트 수준에 있는 옵션을 선택하세요.

3. 이미지 준비 및 선택

표시된 버튼에 따라 Upload, Replace 또는 Select image를 선택하세요. 정사각형 PNG를 고른 뒤, 이미지가 늘어나지 않도록 심볼이 프레임을 가득 채우게 크롭하세요. 전체 로고가 가장자리까지 닿도록 확대하기보다 심볼 주변에 약간의 여백을 남기는 편이 좋습니다.

실제 브라우저 탭 크기에서 결과를 확인하세요. 디자인이 지나치게 복잡하다면 원본 파일로 돌아가 간소화하세요. 아주 작은 raster 이미지를 확대하면 흐림만 더 두드러질 뿐입니다.

4. favicon 적용

미리보기를 확인한 다음 Apply, Save 또는 이에 해당하는 확인 버튼을 선택합니다. 편집기 미리보기에 아이콘이 표시되는지 확인합니다. 일부 편집기 버전은 미리보기를 즉시 업데이트하지만, 다른 버전은 게시 후에만 변경 사항을 표시합니다.

5. 변경 사항 게시

편집기 상단 도구 모음에서 Publish를 선택하고 게시 확인이 표시될 때까지 기다립니다. 편집기 캔버스가 아닌 실제 도메인을 새 탭에서 여세요. 게시되지 않은 변경 사항은 편집기에서는 정상적으로 보이더라도 방문자에게 이전 사이트 파일이 계속 제공될 수 있습니다.

6. 실제 icon request 확인

실제 페이지의 소스를 열어 문서의 <head>에 아이콘 링크가 있는지 확인합니다. rel='icon'에 관한 HTML specification은 페이지를 나타내는 아이콘의 링크 관계를 정의합니다. 기본 제공 기능으로 생성된 결과는 다음과 같을 수 있습니다:

<link rel='icon' href='/favicon.ico'>

브라우저의 Developer Tools에서 Network 패널을 열고 실제 페이지를 새로고침한 다음 icon request를 찾습니다. 요청이 성공적으로 응답하고 업로드한 파일을 가리키는지 확인합니다. 실제 HTML에 아이콘 링크가 없다면 중복 태그를 추가하지 말고 2단계로 돌아갑니다.

7. 필요할 때만 수동 fallback 사용

기본 제공 컨트롤이 원하는 ICO 또는 SVG를 지원하지 않는 경우에는 편집기에 custom HTML 또는 document-head 필드가 있을 때만 fallback을 추가합니다. 각 파일을 안정적인 public URL에 업로드한 다음 head에서 해당 URL을 정확히 참조합니다. /favicon.ico와 같은 path가 존재한다고 가정하지 말고, 해당 위치에 업로드한 뒤 사용합니다.

<link rel='icon' href='/favicon.ico'>
<link rel='icon' type='image/png' sizes='32x32' href='/favicon-32x32.png'>
<link rel='icon' type='image/svg+xml' href='/favicon.svg'>
<link rel='apple-touch-icon' sizes='180x180' href='/apple-touch-icon.png'>

각 sample path를 실제로 게시된 URL로 바꾸고, Website Builder가 이미 생성한 중복 아이콘 태그를 제거합니다. 요금제나 편집기에서 custom-head control을 사용할 수 없다면 기본 제공 uploader를 사용합니다.

흔한 실수

미리보기는 변경되었지만 실제 사이트는 변경되지 않는 경우

사이트를 게시한 뒤 공개 URL을 테스트합니다. 브라우저 탭 아이콘은 캐시에 남아 있을 수 있으므로, 이미지를 다시 변경하기 전에 private window를 사용하거나 favicon cache 삭제 방법의 cache 삭제 절차를 따르세요.

브라우저가 존재하지 않는 파일을 요청하는 경우

게시된 페이지의 <head>에 있는 아이콘 URL을 Network 패널과 비교해 보세요. 404 오류가 발생하는 일반적인 이유는 파일이 다른 경로에 업로드되었거나, URL이 오래되었거나, 수동으로 추가한 markup가 존재하지 않는 위치를 가리키기 때문입니다. 기본 tag는 있지만 아이콘이 표시되지 않는다면, 더 포괄적인 Favicon Not Showing 체크리스트를 따르세요.

아이콘이 잘리거나 늘어나거나 보이지 않는 경우

정사각형 원본 이미지를 업로드하고 아이콘을 가운데 안전 영역 안에 배치하세요. 탭 배경에 투명도가 적용되어 아이콘이 사라진다면, 단색 배경이 있는 버전을 내보낸 후 16×16 px 크기에서 비교해 보세요.

탭에 여전히 이전 브랜드 아이콘이 표시되는 경우

GoDaddy가 저장하지 못했다고 판단하기 전에 게시된 페이지의 markup를 확인하세요. 새 파일을 가리키고 있다면 favicon cache를 삭제하세요. 이전 파일을 가리키고 있다면 다시 게시한 뒤, 오래된 템플릿이나 중복된 아이콘 link가 업로드를 덮어쓰지 않는지 확인하세요.

실제 페이지에서 마지막으로 확인하기

게시된 페이지에서 아이콘 요청이 성공하고 브라우저 탭에 의도한 아이콘이 표시되면 설정이 완료된 것입니다. cache와 아이콘 선택 방식은 브라우저나 기기에 따라 달라질 수 있으므로, 두 번째 브라우저나 기기에서도 같은 확인을 반복하세요. 이렇게 하면 향후 GoDaddy 사이트의 브랜드를 변경할 때마다 활용할 수 있는 일관된 절차를 갖게 됩니다.

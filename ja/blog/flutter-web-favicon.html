Flutter Webのfaviconを正しく設定する

Flutter WebアプリのブラウザタブにデフォルトのFlutterマークが表示されている場合、通常は修正が必要なのはDartのwidgetではなく、web/index.htmlです。Flutter web faviconは、アプリケーションUIとは別にブラウザがリクエストする静的画像です。

Flutterのweb shellからその画像をリンクし、web-app manifestの画像は別に管理してから、静的出力を再ビルドします。Dartの変更は不要です。

前提条件

  • Webが有効になっていること、またFlutter SDKがChromeをターゲットにできることを確認します。assetsを変更する前にflutter doctorを実行してください。
  • シンプルなシルエットの正方形ソース画像を準備します。タブのサイズでは微細なディテールが失われがちなので、エクスポート前にfaviconのサイズガイドを確認してください。
  • デプロイのベースパス（root、または/portal/のようなサブディレクトリ）を把握してください。これは相対的なicon URLの解決方法に影響します。

Flutter Web faviconを6ステップで追加する

  1. Flutter の Web エントリーファイルを確認する

    web/index.html を開き、rel='icon' を検索します。Flutter のテンプレートにはデフォルトの icon link がすでに含まれている場合があるため、競合する icon 定義が 2 組残らないように、その参照を置き換えてください。

    web/manifest.json も開いてください。この icons 配列は、Web アプリをインストールした状態で表示する画像を提供しますが、上で追加するブラウザータブの icon link の代わりにはなりません。

  2. 静的 icon file を準備する

    Mzu favicondl で正方形の icon set を作成します。SVG、16 ピクセルと 32 ピクセルの PNG、複数サイズの ICO、180 ピクセルの Apple touch icon、manifest 用の 192 ピクセルと 512 ピクセルの PNG を export してください。

    以下の場所に file を配置すると、Flutter がその他の静的 Web asset と同時にこれらをコピーします。

    web/
├── index.html
├── manifest.json
└── icons/
    ├── favicon.svg
    ├── favicon-16.png
    ├── favicon-32.png
    ├── favicon.ico
    ├── apple-touch-icon.png
    ├── icon-192.png
    └── icon-512.png

  3. icon link を HTML head に追加する

    HTML 標準 では、rel='icon' を使って icon resource を関連付けます。web/index.html の <head> element 内に、意図的に構成した 1 組の link を追加してください。

    <link rel='icon' type='image/svg+xml' href='icons/favicon.svg'>
<link rel='icon' type='image/png' sizes='32x32' href='icons/favicon-32.png'>
<link rel='icon' type='image/png' sizes='16x16' href='icons/favicon-16.png'>
<link rel='icon' href='icons/favicon.ico'>
<link rel='apple-touch-icon' href='icons/apple-touch-icon.png'>

    テンプレートの古い icon link は削除してください。Apple touch entry は配置対象が異なるため、単独の link として分けて維持します。

  4. Web app manifest を更新する

    PWA としてインストールされる Flutter Web アプリでは、web/index.html に <link rel='manifest' href='manifest.json'> が含まれていることを確認してください。不足している場合は head 内に link を追加し、web/manifest.json の既存の icons 配列を更新します。manifest のその他の key は変更しないでください。

    [
  {
    "src": "icons/icon-192.png",
    "sizes": "192x192",
    "type": "image/png"
  },
  {
    "src": "icons/icon-512.png",
    "sizes": "512x512",
    "type": "image/png"
  }
]

    これらの file はインストール後の app の各表示領域で使用されます。HTML shell 内で明示した rel='icon' link の代わりにはなりません。

  5. 本番用出力を build して確認する

    本番用サイトを build します。

    flutter build web --release

    build/web/index.html と build/web/icons/ を確認します。build 後の index に新しい link が含まれ、参照されている file がすべて存在していることを確認してください。

    アプリを subdirectory から配信する場合は、ホストが期待する base path と同じ値を指定して build します。

    flutter build web --release --base-href=/portal/

    icons/favicon.svg などの relative path は、生成された base URL を基準に解決されます。

  6. browser developer tools で request を確認する

    本番用の出力をローカルで serve します。

    python3 -m http.server 8000 --directory build/web

    http://localhost:8000 を開きます。browser developer tools で、link が document head にあることを確認します。Network panel で favicon だけに filter し、cache を無効にして reload した後、icon request が 200 を返すことを確認してください。

    デプロイ先の HTTPS URL でも request check を繰り返してください。ローカルの folder が正しくても、ホストが別の base path を使用していたり、asset の配信を block していたりする場合があるためです。

よくある落とし穴

  • 誤ったファイルを編集している: web/index.html を変更してください。build/web/index.html ではありません。次のビルドで生成された出力は置き換えられます。
  • link に Flutter assets を使っている: bundle された asset は HTML head 内で参照できる public URL ではありません。favicon ファイルは web/ に配置してください。
  • 重複した link を残している: plugin が生成した tag も含めて、すべての rel='icon' entry を探 し、意図した1つの icon stack に整理してください。
  • base path を無視している: /portal/icons/favicon.svg が404を返す場合は、icon を変更する前に、Flutter の base path または hosting の rewrite を修正してください。
  • manifest だけ更新している: manifest の entry を更新しても、browser tab に icon が表示される保証はありません。HTML の link も更新してください。
  • cached された tab で判断している: 変更したファイル名を変えるか、URL に version を付けてください。その後、より包括的なfavicon トラブルシューティング checklistを確認してください。

まとめ

Flutter web favicon の準備が整った状態とは、source files が web/ に配置され、HTML に整理された1つの icon stack が含まれ、manifest の path が同じ assets と一致し、production build が参照されているすべてのファイルを配信できる状態を指します。この構成なら、browser tab の icon を Dart の rendering と分離しながら、deployment 上の各アイコンに predictable な URL を確保できます。

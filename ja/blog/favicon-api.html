Favicon APIでサイトアイコンの候補を取得

Partner Directoryの構築で、任意のドメインからWebサイトのアイコンを取得する必要MODULEがあるなら、優れたfavicon APIは、Webサイトアイコンの候補を取得して検証し、安定した1つの結果を返します。/favicon.icoにたまたま置かれている画像をそのまま返すだけではありません。

favicon APIでできること

Mzu favicondlは、サイトのアイコンを見つけてダウンロードまたは変換するためのブラウザ側の手段を提供します。自動化された製品では、画像のURLを信頼済みの出力として扱うのではなく、この検索処理をリソース解決のフェーズとして利用してください。

信頼できるサービスは、4つの役割を担います。

  • Resolve: 入力URLを正規化し、宣言されたアイコンリンクを探す。
  • Fetch: 候補を取得し、サイトのリダイレクトを追従する。
  • Validate: レスポンスが配信可能な画像であることを確認する。
  • Cache: 安定したURLを返しつつ、ソースが変更された場合は更新を許可する。

ルートファイルは引き続き便利なフォールバックですが、すべてではありません。HTML Standardでは、ページを表す外部リソースのlink relationとしてiconが挙げられているため、/favicon.icoにフォールバックする前に、宣言されたリンクを確認することをお勧めします。

guide: Webサイトのアイコンを1つ取得する

  1. Mzu favicondlを開き、サイトの完全なHTTPS URLを入力します。
  2. 検索処理を実行し、検出されたアイコンの候補を確認します。
  3. 用途に合うソースを選択します。browser favicon、Apple Touch Icon、manifest iconなどです。
  4. ファイルをダウンロードするか、必要な形式に変換します。ICO、PNG、SVGなどに対応しています。

ドメイン全体で使う1つのアイデンティティが必要な場合は、まずサイトのホームページから始めてください。異なるアイコンを意図的に分けている場合にのみ、ページ固有のURLを使用します。

結果が返らない場合は、そのページが公開アクセス可能か確認し、アイコンの宣言を調べてください。結果が得られない原因には、取得がブロックされている、クライアントサイドレンダリングのページ、利用可能なアイコンがないことなどが考えられ、そのドメインにブランドアセットが存在しないことを意味するものではありません。

favicon APIがWebサイトのアイコンを取得する仕組み

検索処理をアプリケーション内で実行する必要がある場合は、探索と配信を分離してください。Mzu favicondlは、実際の候補を確認したりアセットを変換したり화에引き続き利用できます。ligationは、結果をJSONまたは画像バイトとして公開できます。

以下の Node.js resolver は、ページ HTML を読み込み、rel リストに icon が含まれる link 要素を選択し、その URL を解決して画像を取得します。HTML の解析には Cheerio を使用します。

import { load } from 'cheerio';

export async function getWebsiteIcon(inputUrl) {
  const pageUrl = new URL(inputUrl);
  const pageResponse = await fetch(pageUrl, {
    headers: { 'User-Agent': 'FaviconResolver/1.0' },
  });

  if (!pageResponse.ok) {
    throw new Error(`Page request failed: ${pageResponse.status}`);
  }

  const contentType = pageResponse.headers.get('content-type') || '';
  if (!contentType.includes('text/html')) {
    throw new Error('The target did not return HTML');
  }

  const $ = load(await pageResponse.text());
  const iconLink = $('link[rel~=icon]').first();
  const href = iconLink.attr('href');
  if (!href) return null;

  const finalPageUrl = new URL(pageResponse.url);
  const iconUrl = new URL(href, finalPageUrl);
  const iconResponse = await fetch(iconUrl);

  if (!iconResponse.ok) {
    throw new Error(`Icon request failed: ${iconResponse.status}`);
  }

  return {
    sourceUrl: iconUrl.href,
    finalUrl: iconResponse.url,
    contentType: iconResponse.headers.get('content-type') || '',
    bytes: Buffer.from(await iconResponse.arrayBuffer()),
  };
}

このコンパクトな例は、意図的に不完全なものです。ユーザーから任意の URL を受け付ける前に、private および link-local アドレスへのリクエストをブロックし、redirect の回数と response size に上限を設け、timeout を設定してください。これらの制御は、server-side request forgery（SSRF）や過大なダウンロードの防止に役立ちます。

ホスティング型のサービスを使う場合は、provider を選ぶ前にDuckDuckGo favicon API 比較を確認してください。backend が PHP を使っている場合は、PHP で favicon を取得するチュートリアルで、関連する resolve-and-save ワークフローを解説しています。

アセットを返す前に検証する

  • http と https の URL のみ許可します。
  • 相対リンクは、redirect 後の最終ページ URL を基準に解決します。
  • content type と file signature の両方をチェックします。ファイル名が .png であることは何も証明しません。
  • service が active な SVG content を再ホストする場合は、その内容を拒否またはサニタイズします。

信頼できる icon service の重要機能

取得元の透明性

選択したsource URL、final URL、検出されたmedia type、更新メタデータを返します。これにより、クライアントはアイコンが選定された理由を説明でき、cache invalidationも可能になります。

元のファイルを置き換えない変換

ダウンロードしたsourceは元のまま保持し、利用側ごとに配信用コピーを作成します。複数サイズのraster containerが想定される場合はICO、単一のraster imageにはPNG、自由に拡大縮小できる出力にはSVGを使います。

安定したcache管理

cache entryのkeyには、normalizedしたsite URLとsource icon URLを使います。assetが変更されていない間は再利用できますが、bytesが変わった場合は新しいversioned URLを公開してください。これにより、クライアントが古いlogoを表示し続けることを防げます。

信頼性の高いlookupのためのヒント

  • すべてのcandidateと採用されたsourceを保持します。debuggingが大幅に簡単になります。
  • domain名だけからiconを推測しないでください。
  • final assetを一度だけ取得し、formatの統一やorigin policyの適用が必要なら、制御されたcopyを配信してください。
  • 利用可能な場合はETagまたはLast-Modifiedを使い、不要なtransferを避けてください。
  • 新しいタブで返されたURLを確認してください。空のresponseでもsuccessful status codeになることがあります。

Conclusion

信頼できるfavicon APIは、宣言されたresourceを解決し、返されたbytesを検証し、cacheできるほど安定した結果を提供します。lookupとconversionにはMzu favicondlを使い、workflowでautomationが必要になった場合は、これらのruleを独自のendpointで処理してください。

Link rel shortcut icon の解説：2026年に使用をやめるべき理由

完璧だと思っていたHTMLをW3Cバリデーターにかけたとき、faviconのタグで謎の警告を出された経験はありませんか？バリデーターは <link rel='shortcut icon' href='/favicon.ico'> というタグを無効だと判定します。おそらく、古いチュートリアルやレガシーなコードベースからコピペしたのでしょう。今日、link rel shortcut icon の解説を理解することは、フロントエンド開発者の登竜門となっています。なぜこの特定の属性の組み合わせが存在するのか、ブラウザがそれをどう解釈するのか、そして2026年の今、なぜその半分を削除しなければならないのかを徹底解剖します。

Shortcut Icon の誕生秘話

この混乱を理解するには、Internet Explorer 5の時代まで遡る必要があります。1999年、Microsoftはサイトアイコンという概念を導入しました。ユーザーがウェブサイトのブックマーク（Windowsでは「ショートカット」と呼んでいました）をデスクトップに保存する際、カスタム画像を表示させたいと考えたのです。そこでMicrosoftのエンジニアは急遽、shortcut icon というリレーションタイプを作り出しました。

これは完全にMicrosoft独自の拡張機能であり、当時の公式なHTML仕様ではありませんでした。しかし、IEのアドレスバーや「お気に入り」メニューに自社のアイコンを表示させたいウェブマスターたちは、こぞってこれを採用しました。こうして何年もの間、非公式であるにもかかわらず、これがサイトアイコンを宣言する絶対的な標準となってしまったのです。

ブラウザは Rel 属性をどう解析しているか

ここからが技術的な解析の面白いところです。HTMLの rel 属性は「relationship（関係）」を意味し、現在のドキュメントとリンク先リソースとの関係を定義します。重要なのは、rel 属性はスペース区切りの値のリストを受け入れるということです。

現代のブラウザが rel='shortcut icon' を読み取るとき、「shortcut icon」という1つの関係を見ているわけではありません。以下の2つの独立した関係として認識します。

  • shortcut: レガシーで、仕様上認識されていないリンクタイプ。
  • icon: faviconのための公式なHTML標準リンクタイプ。

HTML仕様では、「icon」を有効な関係として定義しています。これはブラウザに「この画像をUIのアイコンとして使ってね」と伝えます。しかし、「shortcut」は現代のHTMLにおいては全く無意味です。登録されたリンクタイプではありません。両方の単語を使った場合、現代のブラウザは単に「shortcut」を無視し、「icon」だけを処理します。W3Cバリデーターがエラーを出すのは、仕様に存在しない関係タイプを宣言しているからです。

もし "Shortcut" だけで記述したら？

もし <link rel='shortcut' href='/favicon.ico'> と書いた場合、ほぼすべてのブラウザでアイコンの読み込みに失敗します。「shortcut」は認識されるアイコンの関係ではないため、ChromeやSafariはそのファイルを完全に無視します。魔法を起こしていたのは、常に隣にある「icon」という単語だったのです。開発者たちが20年間も「shortcut icon」と打ち込み続けながら、実は後半部分しか仕事仕事をしていなかったというのは、ウェブの歴史の中でもかなり笑える奇妙な事実です。

実際の事例と最新の標準

現在のGitHubやStripeのソースコードを見てみてください。faviconの宣言の近くに「shortcut」という単語は一切見当たりません。彼らはクリーンで標準的なタグを使用しています。GitHubは最新のSVGアイコンとフォールバック用のPNGを提供し、標準の rel='icon' 属性に完全に依存しています。IE5時代のレガシーなハックにしがみつくことは、ドキュメントのheadに無駄なバイト数を追加するだけだと知っているからです。

2026年のベストプラクティス

レガシーな構文を使うのはやめましょう。2026年にサイトを構築する場合、ベースとなるfaviconタグは次のようになります。

<link rel='icon' href='/favicon.ico' sizes='32x32'>

「shortcut」という単語がないことに注目してください。このクリーンな構文は、Chrome、Firefox、Safari、Edgeなど、すべての最新ブラウザで完全にサポートされています。古いブラウザを心配する必要はありません。すでに死に絶えたIE11でさえ、ファイルが有効なICOフォーマットである限り、標準の rel='icon' 構文をサポートしていました。レガシーなコンテナフォーマットについて復習したい場合は、ICOファイルフォーマットのガイドをご覧ください。

SEOとパフォーマンスへの影響

無効な rel 属性があるからといって、Googleのランキングが直接下がるわけではありません。しかし、検索エンジンは検索結果にサイトアイコンを表示するためにドキュメントのheadを解析します。Google自身のドキュメントでも、開発者に rel='icon' を使用するよう明確に求めています。検索エンジンのボットに無効なレガシーマークアップを食わせるのは不必要なリスクです。<head> タグ内の1バイト1バイトが重要です。廃止された属性を削除することで、たとえ微小な差であっても解析速度が向上します。

適切なアイコンスタックの構築

今日、完全なアイコンスタックには単一のICOファイル以上のものが必要です。ダークモード用のSVG、iOS用のApple Touch Icon、Android用のウェブマニフェストが必要です。これらのタグを手動で書くのは面倒でエラーが発生しやすくなります。

Figma faviconのエクスポートとWeb実装

Figma faviconのエクスポートとサイトへの追加方法

ブランドをFigmaで設計していても、ブラウザのタブにはまだ一般的なページアイコンしか表示されない場合、不足しているのは多くのケースで出力と公開の工程です。Figmaのfaviconは正方形のフレームから始まりますが、ブラウザが必要とするのは完成済みのファイルとHTMLリンクです。この手順で、キャンバス上のデザインからサイトへ公開できる状態になったアイコンまで進められます。

前提条件

  • Figma editorへのアクセスと、ブランド素材を含むファイルへの権限。
  • 小さいサイズにも適合できるロゴ、シンボル、またはその他のマーク。
  • エクスポート済みのPNGまたはSVGファイル。
  • サイトの静的アセットを公開するフォルダまたはbuild pipelineへのアクセス。

Figma faviconを作成してエクスポートする

  1. 1. 正方形のマスターフレームを作成する

    Figma の Frame ツールでキャンバスをクリックし、Width と Height の両方を 512 に設定します。フレーム名を Favicon / Master に変更し、簡略化したブランドマークを少し余白を取って配置します。タブに表示されるサイズから始めるのではなく、大きくデザインしてから縮小した方が、より細かく制御できます。

    ワードマークの場合は、横長のロゴ全体を一律に縮小するのではなく、最初の文字または記号だけを複製します。拡大した状態で、最小のカウンター（文字内の空き）とストロークの接合部を確認します。Figma のピクセルグリッドを使えば、16 × 16 px に縮小しても残る隙間かどうかを判断できます。エクスポート前に、細かい部分を簡略化してください。

  2. 2. アートワークを component としてパッケージする

    完成したフレームから component を作成し、その下でレイヤーを Icon/Background や Icon/Mark などの明確な名前でグループ化します。ライト版とダーク版が必要なら、同じジオメトリを持つ component variants を作成します。管理された variants をエクスポートすることで、小さな手動修正が favicon の不統一につながるのを防げます。

  3. 3. PNG と SVG のマスターをエクスポートする

    マスターフレームを選択し、Figma の右サイドバーにある Export を開きます。PNG export を追加し、1× のまま 512 px の画像をエクスポートします。SVG export も追加します。PNG は raster source として使い、SVG は vector geometry を保持します。そのため、SVG は対応しているブラウザーで利用できます。

    エクスポート後、PNG を別のビューアーで開き、キャンバスが正方形、マークが中心、背景が意図した色になっているか確認します。これにより、favicon への変換前に、誤って選択したグループや不要な透明余白を検出できます。

  4. 4. 小さいサイズのファイル一式を生成する

    Mzu favicondl を使って、PNG または SVG を、複数サイズを収録した favicon.ico と、サイトに必要なサイズの PNG ファイルに変換します。拡張子だけを .ico に変更した PNG をアップロードするのではなく、元の SVG は保持してください。favicon size guide では、16、32、48、180、192、512 px のファイルがそれぞれ使用される場面を確認できます。

  5. 5. HTML に icon link を追加する

    次のコードをドキュメントの <head> 内に貼り付けます。アセットが別の場所にある場合は、path を調整してください。

    <link rel='icon' href='/favicon.ico' sizes='any'>
<link rel='icon' href='/favicon.svg' type='image/svg+xml'>
<link rel='icon' href='/favicon-32.png' type='image/png' sizes='32x32'>
<link rel='icon' href='/favicon-192.png' type='image/png' sizes='192x192'>
<link rel='apple-touch-icon' href='/apple-touch-icon.png' sizes='180x180'>

    HTML Living Standard では、icon リソースを宣言するための rel='icon' リンクが定義されています。各 path は、サーバー上で公開しているファイル名と常に一致させてください。

  6. 6. 一致する path にファイルを公開する

    ファイルを、サイトが実際に配信するディレクトリに配置します。ルートに配置する場合、次の構成を使用できます。

    /
├── favicon.ico
├── favicon.svg
├── favicon-32.png
├── favicon-192.png
└── apple-touch-icon.png

    バンドル型の project では、配置先は public/、static/、または別の設定済みアセットフォルダーになる場合があります。デプロイメントパイプラインがそのフォルダーを自動的に処理しない場合は、ビルド出力にもファイルをコピーしてください。

  7. 7. ライブのレスポンスを検証する

    静的プレビューを確認するには、index.html を含むフォルダーで python3 -m http.server 8000 を実行し、http://localhost:8000 を開きます。これにより、サーバーが使用するのと同じ HTTP path を検証でき、file URL の挙動を避けられます。

    DevTools を開き、Network を選択して、favicon で絞り込みます。リクエストされた各ファイルが成功レスポンスを返し、画像として開けることを確認してください。キャッシュされた1つの表示だけに頼らず、ブラウザータブ、ブックマーク、新しく開いたタブを確認します。icon が表示されない、または古いままなら、デザインを変更する前に favicon troubleshooting checklist を使用してください。

よくある落とし穴

  • ロゴ全体を書き出す。 favicon に必要なのは、認識しやすい1つのマークです。wordmark や横長ロゴの全体ではありません。
  • 細かいディテールを使う。 Hairline、小さな文字、低コントラストの色は、16 × 16ピクセルでは消えてしまいます。raster export をシャープにするのではなく、マスターを簡略化してください。
  • 形式と名前を混同する。 拡張子を .ico に変更した PNG も、形式は PNG のままです。ファイル名を変更するのではなく、ICO コンテナを生成してください。
  • 誤ったフォルダーに公開する。 source directory に置いたファイルは、公開 сайтеにコピーされない可能性があります。最終的な公開URLで動作を確認してください。
  • SVG だけ relyingする。 SVG を表示できない環境に備え、ICO や PNG の fallback も用意してください。
  • モバイルアイコンを無視する。 Apple touch icon は別のアセットです。デスクトップのタブ表示用画像を書き出しても、touch icon が自動生成されるわけではありません。

Conclusion

これで、Figma file から本番環境までに明確な流れができました。square component を設計し、PNG と SVG のマスターを書き出し、fallback format を生成して公開し、page head に宣言します。source component は編集可能な状態に保ち、今後のブランド変更が1つの一元管理されたアセットから始まるようにしてください。

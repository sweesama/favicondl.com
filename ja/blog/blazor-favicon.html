Blazor Favicon 設定：実践的なステップ別ガイド

Blazor アプリが動作しているのに、タブに表示されるアイコンが一般的なドキュメントアイコンなら、原因は通常、static file または head 内の link が欠けていることです。確実に機能する Blazor favicon には、次の両方が必要です。アプリが配信するアセットと、document head 内の rel='icon' link です。同じアプローチは Blazor の一般的なホスティングモデルでも使用できます。

前提条件

既存の Blazor プロジェクト、その .NET SDK、正方形のロゴを用意します。元画像が PNG の場合は、Mzu favicondl を使って SVG、ICO、PNG の variant を作成できます。

  • Blazor Web App: 共有 document は Components/App.razor にあります。
  • Standalone WebAssembly: document は wwwroot/index.html にあります。
  • Hosted WebAssembly: client index と、それを公開する server project を特定します。

1. テンプレートと head ファイルを確認する

上記のファイルを開き、head を確認します。Blazor Web App では Components/App.razor を、Standalone WebAssembly では wwwroot/index.html を編集します。Hosted WebAssembly では client index を編集しますが、deploy された server がその assets を配信するかも確認します。古いテンプレートで Pages/_Host.cshtml を使用している場合は、その document を編集します。グローバルな icon は通常の page component には配置しないでください。そこでは 1 つの route にだけ適用される可能性があります。

2. 小さな icon set を用意する

各 variant 用の folder を作成します。

wwwroot/
└── favicon/
    ├── favicon.svg
    ├── favicon.ico
    └── apple-touch-icon.png

これらのファイルを wwwroot の下に配置すると、static web assets として公開されます。拡大縮小可能な SVG、16 px、32 px、48 px の画像を含む ICO、タッチショートカット用の任意の 180×180 PNG を推奨します。余白を持つ正方形の artwork を使用し、小さな文字は削除してください。小さな文字は 16 px では消えてしまいます。ファイルの変換やパッケージ化には Mzu favicondl を使用します。

3. document head に Blazor favicon links を追加する

base URL と stylesheet links を含む同じ head 内に、global links を追加します：

<head>
  <base href='/' />

  <link rel='icon' href='favicon/favicon.ico'
        sizes='16x16 32x32 48x48' />
  <link rel='icon' type='image/svg+xml'
        href='favicon/favicon.svg' />
  <link rel='apple-touch-icon' sizes='180x180'
        href='favicon/apple-touch-icon.png' />
</head>

これらの相対 URL は、ドメインのルートを仮定するのではなく、アプリの base path に従います。HTML Standard の rel='icon' の定義は、外部リソースのアイコンを示しています。type と sizes はファイルを示します。ICO のリンクは fallback として保持し、各コンポーネントで繰り返すのではなく、アプリ全体で共用する一組として定義してください。

4. WebAssembly プロジェクトを更新する

standalone WebAssembly の場合は、同じリンクを wwwroot/index.html の head に貼り付けます。hosted WebAssembly の場合は、クライアント側の index にリンクを追加し、solution を publish したうえで server 側の出力を確認します。

dotnet publish -c Release

publish された wwwroot に favicon フォルダが含まれていることを確認します。含まれていない場合は、host の wwwroot にコピーするか、static-asset の publish 設定を調整します。クライアント側の index が正常に動作していても、アイコンが 404 を返すことはあります。

5. static-file の配信を確認する

アイコンへの直接リクエストが 404 を返す場合は、Program.cs に app.UseStaticFiles() または既存の static-assets endpoint mapping があるか確認します。どちらも存在しない場合は、routing と endpoint registration より前に、次の行を追加します。

app.UseStaticFiles();

pipeline を置き換えたり、既存の static-asset 処理を重複させたりしないでください。この手順を省略すると、ページは描画できる一方、/favicon/favicon.ico へのリクエストは失敗することがあります。standalone WebAssembly では、publish された出力が静的サイトであるため、ASP.NET Core middleware は必要ありません。

6. ファイルとブラウザタブを確認する

プロジェクトを dotnet run で実行し、次の 5000 を実行時に表示されたポートに置き換えて、両方のファイルを直接リクエストします。

curl -I http://localhost:5000/favicon/favicon.ico
curl -I http://localhost:5000/favicon/favicon.svg

各レスポンスは 200 を返し、image content type になっている必要があります。ページのソースを表示し、link 要素が head にあることを確認します。HTML が正しくても、タブに古いアイコンが表示される場合は、新しいタブまたはプライベートウィンドウを開き、Network パネルを点検します。通常のハードリロードでは、すでにキャッシュされたアイコンが置き換えられないことがあります。

同じ確認をデプロイ済みの URL でも行ってください。localhost で成功しても、本番環境で同じベースパスが使用されている、または同じファイルが配信されていることを証明するものではありません。

よくある落とし穴

  • アイコンが 404 になる場合： ファイルが wwwroot/favicon の下にあること、相対パスが一致していること、static files がマッピングされていることを確認してください。
  • localhost では動作するが、サブパスでは失敗する場合： Blazor のベース URL が別の场所を指している場合は、ルート限定の /favicon/... URL を避け、示されたとおりリンクを相対的にしてください。
  • アイコンが重複している、または古い場合： テンプレートの古い favicon link を削除し、新しいタブを使用します。 Antonia080536 に限定したチェックリストについては、localhost での favicon 表示トラブルシューティングガイドを参照してください。
  • いずれかの形式が失敗する場合： 有効な自己完結型の SVG を出力し、複数サイズの ICO をフォールバックとして残してください。外部のスタイルやリソースがあると、SVG を favicon として信頼できなくなる場合があります。

まとめ

hosting model と head ファイルが適合するようにし、アセットを wwwroot の下に配置して、相対的なグローバル URL を宣言します。タブの動作を調査する前に、各ファイルを直接テストしてください。標準外のサーバー構成については、より一般的なASP.NET Core favicon setupのリファレンスを参照してください。

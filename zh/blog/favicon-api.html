Favicon API：获取网站图标候选

如果你正在构建一个合作伙伴目录，需要从任意域名获取网站图标，一个靠谱的 favicon API 应该先收集网站图标候选，逐一验证，再返回稳定结果，而不是直接把 /favicon.ico 上碰巧存在的文件交出来。

favicon API 能做什么

Mzu favicondl 提供了一条在浏览器端查找站点图标并下载或转换图标的路径。在自动化产品中，应把这项查询用作资源解析阶段，而不能直接把输出的图片 URL 当作可信结果。

一个可靠的服务需要完成四项工作：

  • 解析：规范化输入 URL，并查找页面声明的图标链接。
  • 获取：获取候选图标，并跟随网站的 redirects。
  • 验证：确认响应确实是可以提供的图片。
  • 缓存：返回稳定的 URL，同时允许在源文件发生变化后更新。

根目录文件仍然适合作为 fallback，但答案并不只有它。HTML Standard 将 icon 列为一种 link relation，用于表示页面的外部资源，因此建议先检查页面声明的链接，再回退到 /favicon.ico。

入门：获取一个网站图标

  1. 打开 Mzu favicondl，输入该站点的完整 HTTPS URL。
  2. 执行查询，然后检查找到的图标候选。
  3. 根据用途选择合适的来源：browser favicon、Apple Touch Icon 或 manifest icon。
  4. 下载文件，或按需转换为 ICO、PNG 或 SVG。

如果整个域名只需要一个统一标识，先从网站首页开始。只有在有意为不同页面使用不同图标时，才应指定特定页面的 URL。

如果没有返回任何结果，请确认页面可以被公开访问，并检查它的图标声明。没有结果可能意味着抓取被阻止、页面由客户端渲染，或没有可用图标，并不代表该域名没有品牌素材。

favicon API 如何获取网站图标

如果查询必须在你的应用内部运行，应将图标发现与结果交付分开。Mzu favicondl 仍可用于检查真实候选图标和转换资源；你的服务可以将结果以 JSON 或图片字节的形式对外提供。

下面的 Node.js 解析器会读取页面 HTML，找到一个 rel 列表中包含 icon 的链接，解析该链接的 URL，然后获取图片。它使用 Cheerio 解析 HTML。

import { load } from 'cheerio';

export async function getWebsiteIcon(inputUrl) {
  const pageUrl = new URL(inputUrl);
  const pageResponse = await fetch(pageUrl, {
    headers: { 'User-Agent': 'FaviconResolver/1.0' },
  });

  if (!pageResponse.ok) {
    throw new Error(`Page request failed: ${pageResponse.status}`);
  }

  const contentType = pageResponse.headers.get('content-type') || '';
  if (!contentType.includes('text/html')) {
    throw new Error('The target did not return HTML');
  }

  const $ = load(await pageResponse.text());
  const iconLink = $('link[rel~=icon]').first();
  const href = iconLink.attr('href');
  if (!href) return null;

  const finalPageUrl = new URL(pageResponse.url);
  const iconUrl = new URL(href, finalPageUrl);
  const iconResponse = await fetch(iconUrl);

  if (!iconResponse.ok) {
    throw new Error(`Icon request failed: ${iconResponse.status}`);
  }

  return {
    sourceUrl: iconUrl.href,
    finalUrl: iconResponse.url,
    contentType: iconResponse.headers.get('content-type') || '',
    bytes: Buffer.from(await iconResponse.arrayBuffer()),
  };
}

这个精简示例有意保持不完整。在接收公众提交的任意 URL 之前，应拦截指向私有地址和链路本地地址的请求，限制重定向次数和响应大小，并设置超时时间。这些控制措施有助于防止服务器端请求伪造（SSRF）和超大文件下载。

如果使用托管服务，在选择服务商之前，请先查看DuckDuckGo favicon API 对比。如果你的后端使用 PHP，PHP 获取 favicon 教程介绍了相关的解析并保存流程。

返回资源前先校验

  • 仅允许 http 和 https URL。
  • 以最终重定向后的页面 URL 为基准解析相对链接。
  • 同时检查 content type 和文件签名；仅凭 .png 文件名无法判断文件类型。
  • 如果你的服务会重新托管 SVG 内容，请拒绝或净化其中的活动内容。

可靠图标服务的关键特性

来源透明性

返回选定的源 URL、最终 URL、检测到的媒体类型和更新元数据。这样，客户端既能解释为何选中某个图标，也能实现缓存失效。

转换但不替换原文件

保留下载的源文件原样，再针对不同使用方创建交付副本。需要容纳多个尺寸的位图容器时使用 ICO，单张位图使用 PNG，需要可缩放的输出时使用 SVG。

稳定缓存

以规范化后的站点 URL 和源图标 URL 作为缓存键。资源未发生变化时直接复用；字节发生变化时发布带版本的新 URL，避免客户端继续显示旧图标。

可靠查询的实用建议

  • 保留所有候选项和最终选中的来源，调试会容易得多。
  • 不要仅凭域名推断图标。
  • 先获取一次最终资源；如果需要统一格式和来源策略，则提供受控副本。
  • 在可用时使用 ETag 或 Last-Modified 值，避免不必要的传输。
  • 在新标签页中检查返回的 URL；空响应也可能对应成功的状态码。

结语

可靠的 favicon API 会解析已声明的资源、校验返回的字节，并提供足够稳定、可供缓存的结果。交互式查询和转换可使用 Mzu favicondl；工作流需要自动化时，再通过自有 endpoint 实现这些规则。

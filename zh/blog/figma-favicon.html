Figma favicon：导出并添加到网站

如果品牌素材是在 Figma 中设计的，但浏览器标签页仍显示通用页面图标，通常缺的是导出和发布环节。Figma 中的 favicon 起初只是一个方形框，而浏览器需要的是制作完成的文件及对应的 HTML 链接。这一流程会带你从画布一路做到图标上线。

准备工作

  • 能够访问 Figma 编辑器，以及存放品牌素材的文件。
  • 准备一个 logo、符号或其他标识，以便针对小尺寸进行适配。
  • 准备好导出的 PNG 或 SVG 文件。
  • 能够访问用于发布网站静态资源的文件夹或构建流水线（build pipeline）。

创建并导出 Figma favicon

  1. 1. 做一个正方形的主画板

    用 Figma 的 Frame 工具在画布上点一下，把 Width 和 Height 都设成 512。把画板重命名为 Favicon / Master，然后在里面放简化后的品牌标识，四周留一点边距。先按大尺寸画、之后再缩小，比一开始就照着标签页大小画更可控。

    如果用的是文字型 logo（wordmark），复制单个首字母或符号，而不是把整条横排 logo 等比缩小。在高倍缩放下检查最小的字腔（counter）和笔画交接处。Figma 的像素网格能看出某个缝隙在 16 × 16 px 下是否还留得住，所以导出前先把细节简化。

  2. 2. 把 artwork 打包成组件

    从画好的画板创建组件，再把图层按清晰的名字分组，例如 Icon/Background 和 Icon/Mark。如果需要浅色和深色两版，就做成几何完全一致的 component variants。导出这种受控变体，可以避免手工微调造成各尺寸 favicon 之间对不上。

  3. 3. 导出 PNG 和 SVG 主文件

    选中主画板，打开 Figma 右侧边栏的 Export。添加一个 PNG 导出项，倍率保持 1×，导出 512 px 的图片。同时再加一个 SVG 导出项。PNG 提供位图源文件，SVG 则保留矢量几何，供支持它的浏览器使用。

    导出完成后，用另一个看图工具打开这张 PNG，确认画布是正方形、标识居中、背景色就是你要的那一版。这样能在转换之前发现误选中的分组，或者多出来的透明留白。

  4. 4. 生成小尺寸版本

    用 Mzu favicondl 把 PNG 或 SVG 转成一个多尺寸的 favicon.ico，以及你站点需要的各个 PNG 尺寸。别把原始 SVG 扔掉，再把改名为 .ico 的 PNG 传上去。favicon 尺寸指南 里说明了 16、32、48、180、192 和 512 px 这些文件分别用在什么地方。

  5. 5. 在 HTML 里加上图标链接

    把下面这段贴进文档的 <head>，如果资源放在别的目录，就调整路径：

    <link rel='icon' href='/favicon.ico' sizes='any'>
<link rel='icon' href='/favicon.svg' type='image/svg+xml'>
<link rel='icon' href='/favicon-32.png' type='image/png' sizes='32x32'>
<link rel='icon' href='/favicon-192.png' type='image/png' sizes='192x192'>
<link rel='apple-touch-icon' href='/apple-touch-icon.png' sizes='180x180'>

    HTML Living Standard 定义了 rel='icon' 链接，用于声明图标资源。每个路径都要和你服务器上实际发布的文件名保持一致。

  6. 6. 按对应路径发布文件

    把文件放进站点真正会提供的目录。部署在根目录时可以用这样的结构：

    /
├── favicon.ico
├── favicon.svg
├── favicon-32.png
├── favicon-192.png
└── apple-touch-icon.png

    在带打包流程的项目里，这个位置可能是 public/、static/，或其他配置好的资源目录。如果部署流程不会自动处理该目录，也要手动把文件复制到构建产物里。

  7. 7. 验证实际响应

    做静态预览时，在放着 index.html 的目录里执行 python3 -m http.server 8000，然后打开 http://localhost:8000。这样走的就是服务器将来要用的 HTTP 路径，也避开了 file URL 的行为差异。

    打开 DevTools，选 Network，按 favicon 过滤。确认每个被请求的文件都返回成功状态，并且能作为图片打开。分别检查浏览器标签页、书签和新打开的标签，不要只看一个可能已经被缓存的画面。如果图标缺失或者显示的还是旧版本，先照着 favicon 排查清单 逐项核对，再动设计。

常见误区

  • 导出完整 Logo。favicon 需要的是一个辨识度足够的图形标记，而不是文字标或完整的横向 Logo。
  • 使用过多细节。发丝线、微小文字和低对比度颜色到了 16 × 16 像素就会消失。应该简化主视觉，而不是对位图导出结果做锐化处理。
  • 混用格式与扩展名。扩展名为 .ico 的 PNG 文件仍然是 PNG。应生成真正的 ICO 容器，而不是只改扩展名。
  • 发布到错误目录。源目录中的文件可能根本不会被复制到已部署的站点中，因此要测试最终的公开 URL。
  • 只依赖 SVG。对于无法渲染 SVG 的环境，仍应保留 ICO 或 PNG 作为备用格式。
  • 忽略移动端图标。Apple touch icon 是另一份独立资产；导出桌面端标签页图标并不会自动生成它。

结语

现在，你的 Figma 文件已经有了一条清晰的上线路径：设计一个正方形组件，导出 PNG 和 SVG 主文件，生成备用格式，将这些文件发布出去，并在页面 head 中声明它们。保留源组件的可编辑状态，这样以后调整品牌时，就能始终从同一份受控资产出发。

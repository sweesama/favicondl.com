Google Sites favicon：添加与验证分步指南

如果 Google Sites 的 favicon 在浏览器标签页中仍显示为通用地球图标或页面图标，上传内容很可能只进入了草稿；也可能线上站点实际返回的是另一个 icon URL。无需修改主题 XML 就能解决这一问题。

这份分步指南会说明如何添加 Google Sites favicon、发布它，并分别验证浏览器中的图标以及它是否具备在 Google Search 中展示的资格。浏览器验证和 Search 验证是两回事：前者可能已经正常，后者则仍在等待重新抓取。

准备图标并确认站点访问权限

使用能够编辑并发布该站点的浏览器打开 Google Sites。开始前，准备一张正方形图片，可以使用 logo 标志、字母组合或符号；完整的文字标识在 16×16 像素下通常难以辨认。

  • 访问权限：拥有该站点的编辑和发布权限。
  • 源图片：正方形 PNG 是最简单的上传选择。如果要准备实用的源文件，可以使用带有简洁居中标志的 192×192 PNG。
  • 发布 URL：sites.google.com 地址或访客会看到该图标的自定义域名。

Google 文档说明，Search favicon 必须是正方形且至少为 8×8 像素，并建议使用大于 48×48 像素的尺寸。favicon 只是具备被展示的资格，并不保证一定出现，其 URL 也应保持稳定。参见 Google 的 favicon 文档。

如果你的素材是 SVG、JPG 或其他格式，请先转换为正方形 PNG 再上传。Mzu favicondl 可以完成转换；导出前先简化图形，这样浏览器标签页中的版本仍能保留清晰轮廓。

添加 Google Sites favicon，无需自定义代码

  1. 打开站点设置。

    打开 Google Sites 控制面板，选择目标站点，然后点击“编辑”。在编辑器右上角“发布”旁的“更多”或三点菜单中，选择“站点设置”。找到 Favicon 控件并打开文件选择器。

  2. 上传并确认图片。

    选择准备好的 PNG。检查预览或裁剪结果，确保完整标志保持居中且清晰可见，然后保存所选图片。保留足够的纯色对比度，避免图标在深色浏览器标签页中消失。

  3. 发布更新后的站点。

    点击“发布”，确认站点 URL，然后发布更新。在 Site settings 中保存图片不会立即改变访客看到的站点；只有发布新版本后才会生效。

  4. 检查已发布的首页。

    在新标签页中打开已发布的 URL，不要使用编辑器预览。在浏览器开发者工具中检查 document head，找到 icon link。然后在 DevTools 控制台运行以下代码：

    Array.from(document.querySelectorAll('link[rel~=icon]')).map(function (link) {
  return {
    href: link.href,
    type: link.type,
    sizes: link.getAttribute('sizes') || ''
  };
})

    结果中应当至少包含一个 favicon URL。HTML 标准将 rel='icon' 定义为指向图标外部资源的链接，因此应检查链接的实际 URL，不要想当然地认为它一定以 favicon.ico 结尾。

    在 Network 面板中重新加载页面并选择图标请求。返回结果应当是图片响应，而不是 HTML fallback 或 404 响应。

  5. 测试浏览器中的显示结果。

    重新加载已发布的页面，检查标签页、书签和快捷方式。如果仍显示旧图标，请确认控制台中显示的是新的资源 URL，然后尝试使用无痕窗口；浏览器可能会单独缓存 favicon，其缓存方式与普通页面内容不同。

  6. 等待 Google Search 重新抓取。

    按照 Google 的Search favicon 要求检查图标是否为正方形、尺寸是否达到最低要求、URL 是否稳定以及是否允许抓取。发布后，重新抓取可能需要数天到数周，因此 Search 结果不会立即更新，并不代表上传失败。

    如需集中排查搜索结果中缺少图标的问题，请参阅 Google Search favicon 检查清单。

Google Sites favicon 常见误区

  • 只检查编辑器，不检查线上域名： 请确认已发布的主页包含 favicon，而不是只查看编辑预览。
  • 反复替换图标资源： 每次替换都可能生成新的 icon URL。Google 发现该图标后，应保持已发布的 URL 不变。
  • 使用细节过多的 logo： 细线和小字在 16×16 的标签页中会消失。发布前应按该尺寸测试图标。
  • 混淆 cache 问题与 Search 延迟： 浏览器可能已经显示新图标，而 Google Search 仍显示旧图标，也可能情况相反，因为两者的更新路径不同。
  • 添加相互冲突的 icon 标签： 使用 Google Sites 原生上传器时，应避免添加不必要的 HTML 嵌入代码，否则会引入多个 rel='icon' 候选项，让排查变得更困难。

确认最终配置

可靠的操作顺序很简单：在 Site settings 中上传一张正方形 PNG，发布，检查线上主页，然后等待 Google Search 重新抓取。如果你也在管理其他 no-code 平台，可以将这套流程与更通用的 no-code website favicon 指南进行对比。

保持已发布 icon 的 URL 不变；如果品牌资源发生变化，请再次检查 canonical homepage。这样，浏览器用户、书签客户端和 Google 的 crawler 就能引用同一个一致的来源。

Webpack Favicon 配置：分步指南

如果你做过 Webpack 项目，又发现浏览器标签页里只有一个通用地球图标或空白方块，这并不少见。Webpack 不会开箱即用地处理 favicon，需要你自己接入。好在弄清文件放在哪里、再注入 link 标签后，只需几行配置就能搞定。

本文会介绍如何为 Webpack 项目添加 favicon，从放置文件到在浏览器中验证结果。我们会分别说明简单的复制方案和 HtmlWebpackPlugin 方案，并指出大多数开发者容易踩到的坑。

前置条件

你应当已经有一个可以正常运行的 Webpack 项目，并安装了 webpack 和 webpack-cli。如果你使用 html-webpack-plugin 生成 HTML，那会更方便，因为后面的推荐方案会用到它。另外，准备好一个 favicon 文件，格式可以是 ICO、PNG 或 SVG。如果还没有，可以按照我们的指南生成一个包含多种尺寸的 ICO 文件。

步骤 1：将 favicon 放入项目

如果项目中还没有用于存放静态资源的目录，就先创建一个。常见约定是使用 src/assets/ 或 public/。把 favicon 文件放在其中——为了获得最大范围的浏览器兼容性，这里将它命名为 favicon.ico。也可以使用 favicon.png 或 favicon.svg；现代浏览器支持 SVG，但旧版浏览器还需要一个 fallback，参见SVG with PNG fallback。

本文假设文件路径为 src/assets/favicon.ico。

步骤 2：配置 Webpack 复制 favicon

Webpack 需要知道这个文件的存在，才能将它复制到构建产物中。最简单的做法是使用 copy-webpack-plugin。安装它：

npm install --save-dev copy-webpack-plugin

然后将它添加到 webpack.config.js：

const CopyPlugin = require('copy-webpack-plugin');

module.exports = {
  // ... other config
  plugins: [
    new CopyPlugin({
      patterns: [
        { from: 'src/assets/favicon.ico', to: 'favicon.ico' }
      ]
    })
  ]
};

这会将 favicon 复制到输出目录根部（例如 dist/favicon.ico）。如果没有 link 标签，浏览器会自动请求 /favicon.ico，因此仅这一项配置就可能生效；不过，显式添加 link 标签更便于控制，也能支持非 ICO 格式。

第 3 步：使用 HtmlWebpackPlugin 注入 link 标签

如果你在使用 html-webpack-plugin，可以直接在 HTML 模板中添加 favicon link。在 index.html 模板（通常位于 src/ 中）的 <head> 内加入以下内容：

<link rel='icon' href='favicon.ico' type='image/x-icon'>

由于文件会被复制到输出目录根部，相对路径 favicon.ico 就能正确解析。如果站点部署在子目录下，请使用 /favicon.ico 这样的绝对路径，或在 Webpack 中配置 publicPath。

SVG favicon 可写成：

<link rel='icon' href='favicon.svg' type='image/svg+xml'>

PNG 则写成：

<link rel='icon' href='favicon.png' type='image/png'>

HTML 标准将 rel='icon' 属性定义为指定站点图标的方式。浏览器会据此为标签页、书签和历史记录选择最合适的图标。

第 4 步：构建并验证

运行构建命令（例如 npm run build），确认输出文件夹中存在 favicon.ico。然后在本地启动服务来提供构建产物（例如使用 npx serve dist），并用浏览器打开。此时标签页应该会显示你的图标。如果没有，请执行强制刷新（Ctrl+Shift+R 或 Cmd+Shift+R）以绕过缓存。

也可以查看页面源代码，确认 link 标签存在且路径正确。

常见坑点

  • 输出路径不匹配：如果使用 CopyPlugin，并且 to 路径包含子目录，link 标签也必须与之对应。例如，to: 'assets/favicon.ico' 对应的链接应使用 href='assets/favicon.ico'。
  • 生产环境缺少文件：有些配置只在开发阶段复制资源。请确保 CopyPlugin 在所有模式下都会运行。
  • 缓存问题：浏览器会 aggressively 缓存 favicon。更新 favicon 时，可以附加类似 favicon.ico?v=2 的 query string，或者在构建流程中配置 cache busting（参见 cache busting 最佳实践）。
  • SVG 缺少 fallback：较旧的浏览器会忽略 SVG favicon。务必提供 ICO 或 PNG 作为 fallback。
  • 文件不在根目录：如果不使用 link 标签，而是依赖浏览器默认发起的 /favicon.ico 请求，文件就必须放在服务目录的根路径下。

总结

为 Webpack 项目添加 favicon 并不复杂，关键只有两步：把文件复制到输出目录，并在 HTML 中引用它。使用 copy-webpack-plugin 复制资源，再在模板中添加 link rel='icon' 标签即可。这样一来，浏览器标签页就会显得更精致、更专业。

GoDaddy Website Builder favicon 设置指南

如果 GoDaddy 网站在浏览器标签页中仍显示默认图标，新图标可能只是停留在预览状态，也可能是浏览器仍在复用旧图标。GoDaddy Website Builder favicon 是作用于整个网站的浏览器图标，并不是放在页面某个区块内的图片。请在编辑器中上传它、发布网站，然后检查线上 HTML 实际提供的是哪个图标。

准备工作

你需要拥有该 GoDaddy 网站的编辑和发布权限，并准备一张正方形源图。PNG 是比较实用的上传格式；512×512 px 的源图能留出更多空间，方便你在导出前简化图案。即使缩小到 16×16 px，也要让标识保持清晰可辨，因为细线条和细小文字通常会消失。

  • GoDaddy 登录凭据和 Website Builder 网站访问权限
  • 背景清晰的方形 PNG 或 SVG 源图
  • 线上域名 URL，以及带有 Developer Tools 的浏览器

你可以使用 Mzu favicondl 准备最终的 PNG、ICO 和 SVG 变体。原生上传器是最简单的方案；只有在需要手动备用方案时，这些额外格式才有用。

分步添加 GoDaddy Website Builder Favicon

1. 在 Website Builder 中打开网站

登录 GoDaddy，打开 Websites and Shop，选择与你的 Website Builder 网站关联的域名。选择 Edit Website 进入编辑器。如果编辑器已经打开，直接进入下一步。

2. 打开 favicon 设置

打开编辑器的网站级设置面板，找到 Favicon。具体位置取决于当前编辑器布局，该控件可能位于 Settings 下，也可能显示为 Website icon。请选择网站级控件，不要选择区块内的图片区块或常规 logo 字段。

3. 准备并选择图片

根据实际显示的按钮，选择 Upload、Replace 或 Select image。选中方形 PNG 后进行裁剪，让标识在画框中充分占据空间，同时避免拉伸。标识四周应留出一点空间，不要把完整 logo 的边缘直接缩放到画框边缘。

按浏览器标签页的实际尺寸预览效果。如果图案细节太多，请回到源文件进行简化；把小尺寸的 raster image 放大，只会让模糊更加明显。

4. 应用 favicon

确认预览效果，然后选择 应用、保存 或对应的确认按钮。检查编辑器预览中是否已经显示你的图标。有些编辑器版本会立即更新预览，有些则要发布后才会显示更改。

5. 发布更改

在编辑器顶部工具栏选择 发布，然后等待发布确认。在新标签页中打开线上域名，而不是编辑器画布。尚未发布的更改可能在编辑器里显示正常，但访客拿到的仍是上一版站点文件。

6. 验证线上图标请求

打开线上页面的源代码，检查文档的 <head> 中是否有图标链接。HTML 规范中对 rel='icon' 的定义规定了这种用于指向页面图标的链接关系。原生结果可能如下：

<link rel='icon' href='/favicon.ico'>

在浏览器 Developer Tools 中打开 Network 面板，重新加载线上页面，并查找图标请求。确认请求返回了成功响应，且指向你上传的文件。如果线上 HTML 中没有图标链接，请返回第 2 步，而不是自行添加重复标签。

7. 仅在必要时使用手动 fallback

如果原生控件无法接受你偏好的 ICO 或 SVG，只有在编辑器提供自定义 HTML 或 document-head 字段时，才添加 fallback。将每个文件上传到稳定的公开 URL，然后在 head 中引用这些准确的 URL。不要以为像 /favicon.ico 这样的路径已经存在，除非你确实把文件上传到了该位置。

<link rel='icon' href='/favicon.ico'>
<link rel='icon' type='image/png' sizes='32x32' href='/favicon-32x32.png'>
<link rel='icon' type='image/svg+xml' href='/favicon.svg'>
<link rel='apple-touch-icon' sizes='180x180' href='/apple-touch-icon.png'>

将示例中的每个路径替换为真实且已发布的 URL，并删除 Website Builder 已生成的重复图标标签。如果你的套餐或编辑器没有提供 custom-head 控制功能，请改用原生上传工具。

常见问题

预览已更改，但线上站点没有变化

发布网站并测试其公开 URL。浏览器标签页中的图标可能仍来自缓存，因此，在再次更换图片前，请使用无痕窗口，或按照如何清除 Favicon 缓存一文中的步骤清除缓存。

浏览器请求的文件不存在

将线上页面 <head> 中的图标 URL 与 Network 面板中的请求进行对比。出现 404 通常意味着文件上传到了其他路径、URL 仍指向旧位置，或手动添加的标记引用了不存在的地址。如果原生标签已经存在，图标却没有显示，请按照Favicon 未显示一文中更全面的排查清单逐一检查。

图标被裁切、拉伸或看不见

上传正方形源图，并确保图标位于中央安全区域内。如果透明背景导致图标在标签页背景上消失，请导出一张带纯色背景的版本，并在 16×16 px 的尺寸下检查效果。

标签页仍显示旧品牌

先检查线上页面的标记，不要直接认定 GoDaddy 没有保存。如果它指向新文件，请清除 favicon 缓存；如果仍指向旧文件，请重新发布，并检查是否有旧模板或重复的图标链接覆盖了本次上传。

最后检查线上页面

当已发布页面包含成功的图标请求，且浏览器标签页显示预期图标时，说明设置已经完成。请再用第二个浏览器或设备重复检查，因为缓存和图标选择机制可能有所不同。这样，以后每次为 GoDaddy 更换品牌标识时，都可以重复使用这套流程。

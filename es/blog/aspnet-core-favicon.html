Configuración de favicon en ASP.NET Core

Si tu aplicación ASP.NET Core muestra una pestaña del navegador vacía o un símbolo de respaldo en lugar de tu marca, normalmente es porque el icono falta en el <head> renderizado o está guardado fuera de la carpeta expuesta como contenido estático. Un favicon de ASP.NET Core necesita dos elementos: un archivo de icono en wwwroot y una declaración link en el layout compartido.

Esta distinción es importante. Colocar favicon.ico en la raíz del proyecto no lo sitúa dentro de wwwroot, y añadir un archivo a wwwroot no hace que se muestre automáticamente en todas las páginas. Los pasos siguientes se aplican a aplicaciones MVC y Razor Pages que utilizan un layout compartido convencional.

Requisitos previos

  • Una aplicación ASP.NET Core que renderice HTML mediante un archivo _Layout.cshtml compartido.
  • Permiso para editar el layout y la carpeta wwwroot.
  • Un logo cuadrado o un PNG que pueda convertirse a formatos de favicon.

Si tu aplicación tiene layouts separados para las áreas pública, de cuentas o de administración, repite el paso de marcado en cada uno. Una aplicación solo de API no tiene ningún head de página que configurar; en su lugar, añade el favicon a su página de inicio o al host de documentación.

Añade un favicon de ASP.NET Core paso a paso

  1. Prepara un conjunto pequeño de iconos

    Crea esta estructura de carpetas:

    wwwroot/
  favicon.ico
  icons/
    favicon.svg
    favicon-32x32.png
    apple-touch-icon.png

    Usa un ICO que contenga imágenes de 16, 32 y 48 píxeles, un PNG de 32 píxeles y un SVG sencillo. Añade un Apple touch icon de 180 píxeles si los usuarios pueden guardar el sitio en una pantalla de inicio. Si tu archivo de origen es un logo o un PNG, Mzu favicondl puede crear las variantes ICO, PNG y SVG sin modificar el archivo original.

  2. Confirma que se sirven los archivos estáticos

    ASP.NET Core sirve los archivos de wwwroot mediante su middleware de archivos estáticos. Si tu aplicación ya carga CSS o imágenes desde esa carpeta, probablemente este paso esté hecho. De lo contrario, asegúrate de que el pipeline incluya:

    var app = builder.Build();

app.UseStaticFiles();

// Keep your existing routing and endpoint registrations below.

    Añade la llamada una sola vez. Si ya existe una entrada de middleware, no la registres dos veces.

  3. Añade los enlaces dentro del head compartido

    Abre Views/Shared/_Layout.cshtml para MVC o Pages/Shared/_Layout.cshtml para Razor Pages. Coloca estos elementos dentro de <head>, junto a los enlaces de las hojas de estilos:

    <link rel='icon' href='~/favicon.ico' sizes='16x16 32x32 48x48'>
<link rel='icon' href='~/icons/favicon-32x32.png' type='image/png' sizes='32x32'>
<link rel='icon' href='~/icons/favicon.svg' type='image/svg+xml' sizes='any'>
<link rel='apple-touch-icon' href='~/icons/apple-touch-icon.png' sizes='180x180'>

    La forma rel='icon' identifica un recurso de icono externo, tal como se define en la documentación de tipos de enlace de HTML. Las rutas ~/ de Razor mantienen correctas las URL cuando la aplicación se aloja bajo una subruta. Si tu layout no tiene <head>, añade uno antes de insertar los enlaces.

  4. Conserva un ICO de respaldo en la raíz

    El archivo situado en wwwroot/favicon.ico está disponible en /favicon.ico. Como medida de compatibilidad, conserva ese archivo y el enlace explícito al ICO: de este modo, las solicitudes del navegador a la ruta raíz convencional obtienen una respuesta válida aunque una plantilla de página esté incompleta.

  5. Ejecuta la aplicación y comprueba cada respuesta

    Arranca el sitio con dotnet run, abre su URL local y abre las herramientas de desarrollo del navegador. Selecciona el panel Network, filtra por favicon y recarga la página. Cualquier solicitud de icono que aparezca ahí debería responder correctamente con tipos de contenido de imagen, en lugar de devolver respuestas 404. Usa View Source para confirmar que los cuatro elementos de enlace están en el HTML devuelto y, después, comprueba que la pestaña del navegador muestra la marca prevista.

  6. Verifica el sitio publicado

    Despliega la aplicación, inspecciona el código fuente de la página en producción y repite la comprobación en Network. Si el icono funciona localmente pero no en producción, compara los valores href generados con la URL desplegada y confirma que los archivos de iconos están presentes en la salida publicada. Si sigue visible un icono antiguo, prueba una ventana privada antes de investigar un CDN, un service worker o la caché de favicons del navegador.

Problemas habituales

  • Enlaces en el body: Coloca las declaraciones de iconos en el head del documento. Un fragmento de layout también puede fallar al renderizarse si la página no lo utiliza.
  • Archivos fuera de wwwroot: El middleware de archivos estáticos no sirve los archivos ubicados en la raíz del proyecto.
  • Rutas raíz fijadas en el código: Usa ~/ en los layouts de Razor cuando la aplicación pueda ejecutarse bajo un prefijo de ruta.
  • Falta el middleware: Si el panel Network devuelve 404 para cada icono, comprueba primero app.UseStaticFiles().
  • Salida obsoleta: Vuelve a desplegar el contenido actualizado de wwwroot y ten en cuenta el almacenamiento en caché.
  • Arte de origen defectuoso: Elimina el marcado SVG no válido y asegúrate de que cada ICO contiene realmente las capas declaradas.

Si el marcado y las respuestas son correctos, pero la pestaña sigue mostrando el icono equivocado, revisa la guía completa para solucionar problemas con el favicon. Para conocer el proceso basado únicamente en HTML, consulta cómo añadir un favicon a un sitio web.

Termina con una pila de iconos limpia

Tu favicon de ASP.NET Core estará listo cuando los archivos estén en wwwroot, el middleware de archivos estáticos esté activo y el layout compartido declare los candidatos ICO, PNG y SVG. Mantén el favicon.ico en la raíz, verifica las respuestas del despliegue y solo entonces considera que el icono de la pestaña está completo.

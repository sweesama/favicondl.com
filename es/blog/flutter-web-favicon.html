Configura el favicon de Flutter Web paso a paso

Si tu app Flutter Web todavía muestra el icono predeterminado de Flutter en la pestaña del navegador, la solución normalmente está en web/index.html, no en un widget de Dart. El favicon de Flutter Web es una imagen estática que el navegador solicita por separado de la interfaz de tu aplicación.

Deberás enlazar esa imagen desde el shell web de Flutter, mantener separadas las imágenes del manifiesto de la aplicación web y, después, recompilar la salida estática. No hace falta modificar ningún archivo de Dart.

Requisitos previos

  • Comprueba que Web esté habilitado y que tu Flutter SDK pueda apuntar a Chrome. Ejecuta flutter doctor antes de modificar los assets.
  • Prepara una imagen fuente cuadrada con una silueta sencilla. Los detalles pequeños suelen desaparecer al tamaño de una pestaña; consulta la guía de tamaños de favicon antes de exportar.
  • Ten en cuenta la ruta base del despliegue: la raíz o un subdirectorio como /portal/. Esto afecta a la forma en que se resuelven las URL relativas de los iconos.

Añade un favicon para Flutter Web en seis pasos

  1. Revisa el archivo de entrada web de Flutter

    Abre web/index.html y busca rel='icon'. La plantilla de Flutter puede que ya incluya un enlace a un icono predeterminado, así que sustituye esa referencia en lugar de dejar dos conjuntos de enlaces de iconos compitiendo.

    Abre también web/manifest.json. Su array icons proporciona las imágenes de la aplicación web instalada, pero no sustituye el enlace de la pestaña del navegador que añadirás a continuación.

  2. Prepara los archivos estáticos del icono

    Crea un conjunto de iconos cuadrados con Mzu favicondl. Exporta un SVG, PNG de 16 y 32 píxeles, un ICO multirresolución, una imagen Apple touch de 180 píxeles y PNG de 192 y 512 píxeles para el manifest.

    Coloca los archivos en web/icons/ para que Flutter los copie junto con el resto de los assets web estáticos:

    web/
├── index.html
├── manifest.json
└── icons/
    ├── favicon.svg
    ├── favicon-16.png
    ├── favicon-32.png
    ├── favicon.ico
    ├── apple-touch-icon.png
    ├── icon-192.png
    └── icon-512.png

  3. Añade los enlaces del icono al head de HTML

    El estándar HTML asocia un recurso de icono con rel='icon'. Añade dentro del elemento <head> de web/index.html un conjunto de enlaces de icono bien definido:

    <link rel='icon' type='image/svg+xml' href='icons/favicon.svg'>
<link rel='icon' type='image/png' sizes='32x32' href='icons/favicon-32.png'>
<link rel='icon' type='image/png' sizes='16x16' href='icons/favicon-16.png'>
<link rel='icon' href='icons/favicon.ico'>
<link rel='apple-touch-icon' href='icons/apple-touch-icon.png'>

    Elimina los enlaces de iconos antiguos de la plantilla y mantén aparte la entrada Apple touch, porque corresponde a una superficie de visualización diferente.

  4. Actualiza el manifest de la aplicación web

    Para una aplicación web de Flutter instalada como PWA, comprueba que web/index.html contenga <link rel='manifest' href='manifest.json'>. Si falta, añade el enlace dentro del head y actualiza el array icons existente en web/manifest.json. Mantén sin cambios las demás claves del manifest.

    [
  {
    "src": "icons/icon-192.png",
    "sizes": "192x192",
    "type": "image/png"
  },
  {
    "src": "icons/icon-512.png",
    "sizes": "512x512",
    "type": "image/png"
  }
]

    Estos archivos cubren las superficies de visualización de las aplicaciones instaladas; no sustituyen los enlaces rel='icon' explícitos de la estructura HTML.

  5. Compila e inspecciona el output de producción

    Compila el sitio de producción:

    flutter build web --release

    Inspecciona build/web/index.html y build/web/icons/. El index compilado debería contener los nuevos enlaces y todos los archivos referenciados deberían estar presentes.

    Si la aplicación se sirve desde un subdirectorio, compílala con el mismo base path que espera tu host:

    flutter build web --release --base-href=/portal/

    Las rutas relativas, como icons/favicon.svg, se resolverán entonces respecto de esa base URL generada.

  6. Comprueba la petición en las herramientas de desarrollo del navegador

    Sirve localmente el output de producción:

    python3 -m http.server 8000 --directory build/web

    Abre http://localhost:8000. En las herramientas de desarrollo del navegador, confirma que los enlaces están en el document head. En el panel Network, filtra por favicon, desactiva la caché, recarga la página y verifica que la petición del icono devuelve 200.

    Repite la comprobación de la petición en la URL HTTPS desplegada, porque la carpeta local puede estar correcta mientras el host utiliza un base path diferente o bloquea el asset.

Errores comunes

  • Editar el archivo equivocado: Modifica web/index.html, no build/web/index.html; la siguiente compilación reemplaza el output generado.
  • Usar assets de Flutter para el enlace: Un asset empaquetado no es una URL pública en el head del HTML. Coloca los archivos favicon en web/.
  • Dejar enlaces duplicados: Busca todas las entradas rel='icon', incluidas las etiquetas generadas por plugins, y conserva una única pila de iconos deliberada.
  • Ignorar la ruta base: Si /portal/icons/favicon.svg devuelve 404, corrige la ruta base de Flutter o la regla de reescritura del hosting antes de cambiar el icono.
  • Actualizar solo el manifest: Las entradas del manifest no garantizan el icono de la pestaña del navegador. Actualiza también los enlaces del HTML.
  • Juzgar por una pestaña con la caché: Renombra el archivo modificado o versiona su URL y consulta la lista más completa de solución de problemas con el favicon.

Conclusión

Un favicon para Flutter web estará listo cuando los archivos de origen estén en web/, el HTML contenga una única pila de iconos limpia, las rutas del manifest coincidan con esos mismos assets y la compilación de producción sirva todos los archivos referenciados. Esta estructura mantiene el icono de la pestaña del navegador separado del renderizado de Dart y proporciona al despliegue una URL predecible para cada icono.

Configura un favicon en Gradio paso a paso

Si la pestaña del navegador muestra un globo genérico mientras tu app de Gradio carga con normalidad, significa que a la app le faltan los metadatos del icono. La forma más sencilla de añadir un favicon a Gradio es hacerlo desde el launcher, donde Gradio puede registrar el archivo sin que tengas que editar la plantilla de página que genera.

No necesitas insertar una etiqueta <link> dentro de un componente gr.HTML ni duplicar el icono en cada componente. Configúralo una sola vez al iniciar la aplicación y luego comprueba que el navegador solicite realmente el archivo.

Requisitos previos

Antes de empezar, necesitas una aplicación de Gradio que puedas reiniciar, un archivo de icono cuadrado y acceso al proceso que inicia la app.

  • Un proyecto de Gradio con un archivo app.py u otro punto de entrada de Python.
  • Un archivo .ico cuadrado. Para obtener un fallback predecible en el navegador, incluye diseños de 16 px, 32 px y 48 px en el contenedor.
  • Acceso al comando de launch o a la plataforma de hosting, incluido el permiso para leer el archivo del icono.

Si tu diseño empieza como PNG o SVG, conviértelo antes del despliegue. Puedes usar Mzu favicondl para crear el ICO y, después, conserva el archivo generado con el nombre favicon.ico. La guía para convertir PNG a ICO explica las opciones de tamaño.

1. Prepara el archivo favicon

Crea un directorio assets junto al punto de entrada de Python. Guarda el icono en una ruta estable para que todas las copias del proyecto —local, en un contenedor o alojadas— usen la misma referencia.

your-gradio-app/
├── app.py
└── assets/
    └── favicon.ico

Diseña para la pestaña, no para una página de logotipo completa. Una forma audaz o una sola letra suelen conservar mejor su legibilidad en el renderizado de 16 píxeles que un texto con muchos detalles. Mantén el original cuadrado y no dependas de que una imagen ancha se recorte de forma impredecible.

2. Configura el favicon de Gradio con launch()

Pasa la ruta absoluta del archivo al argumento favicon_path de demo.launch(). Esta es la opción específica de Gradio; no la coloques dentro de gr.Blocks().

from pathlib import Path

import gradio as gr

app_dir = Path(__file__).resolve().parent
favicon = app_dir / 'assets' / 'favicon.ico'

if not favicon.is_file():
    raise FileNotFoundError(f'Favicon not found: {favicon}')

with gr.Blocks() as demo:
    gr.Markdown('# My Gradio app')

demo.launch(favicon_path=str(favicon))

La expresión Path(__file__).resolve().parent ancla el icono al script, no al directorio de trabajo actual de la shell. La comprobación is_file() detecta un asset ausente o una ruta mal escrita antes de que la aplicación siga arrancando. Configura esta opción con un archivo local; una URL de imagen remota no sustituye a un asset que pueda incluirse en el despliegue.

3. Verifica el icono localmente

Detén el servidor en ejecución y vuelve a iniciarlo después de cambiar el código. Las pestañas del navegador almacenan los iconos en caché de forma agresiva, así que verifica el resultado en una pestaña nueva o una ventana privada, en lugar de confiar en la pestaña anterior.

Inspecciona el código fuente de la página dentro de <head> y busca un enlace cuyo valor de rel sea icon. La especificación de HTML define icon como una relación de enlace para un recurso externo, lo que permite que el navegador solicite ese archivo por separado de la página de la app.

En las herramientas de desarrollo, abre el panel Network y recarga la página. Comprueba que la solicitud del icono devuelve 200 en lugar de 404 y que la respuesta corresponde al archivo que has subido. Si el enlace existe pero la pestaña todavía muestra el símbolo anterior, consulta la lista completa de troubleshooting de favicon para revisar la caché y los enlaces de iconos conflictivos.

4. Despliega el asset junto con la app

Despliega el icono junto con la aplicación, no solo en tu equipo. El paquete de entrega debe incluir tanto app.py como assets/favicon.ico en las ubicaciones relativas que se muestran arriba.

  • Para una imagen de contenedor, copia el directorio assets en el stage o la imagen final que contenga app.py.
  • Para despliegues basados en Git, haz commit del archivo .ico, salvo que la política de tu hosting guarde los assets binarios en otra ubicación.
  • Para un servidor personalizado, asegúrate de que el comando de inicio ejecute la llamada demo.launch(...) del script; un archivo en el repositorio no puede configurar por sí solo un servidor en ejecución.

La misma comprobación es importante cuando una plataforma ofrece su propia opción para configurar el icono del sitio. Si la app Gradio está incrustada en otra página, el documento principal puede controlar la pestaña del navegador. En ese caso, actualiza también el icono de la página contenedora, además del launcher de Gradio.

Problemas comunes

La mayoría de los intentos fallidos al configurar un favicon en Gradio se deben a algunos errores pequeños:

  • Ubicación incorrecta del argumento: favicon_path pertenece a launch(), no a Blocks() ni a Interface().
  • Ruta relativa frágil: assets/favicon.ico depende del directorio desde el que se inicia el proceso. Anclala a __file__ como se muestra.
  • Archivo de deployment ausente: Que la app funcione correctamente en local no demuestra que el build alojado incluya el archivo .ico.
  • Contenido incorrecto del archivo: No renombres un archivo PNG como favicon.ico; convierte la imagen al formato ICO.
  • Caché del navegador obsoleta: Abre una pestaña nueva o borra los datos del favicon del sitio antes de volver a modificar el código de la aplicación.
  • Conflicto con la página contenedora: Si Gradio está dentro de un iframe, la página exterior todavía puede determinar el icono de la pestaña.

Conclusión

Un favicon de Gradio es más fácil de gestionar como un recurso disponible en el momento del launch: coloca un archivo ICO cuadrado junto a la app, pasa su ruta resuelta a launch(favicon_path=...) y verifica la solicitud del icono renderizado. Así, la implementación se mantiene sencilla y las apps Gradio, tanto locales como alojadas, tienen un único archivo evidente que actualizar cuando cambie la marca.

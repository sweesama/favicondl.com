  "contentEn": "<p>If your ASP.NET Core app still shows a generic globe or the default project icon, the problem is usually the file path, static-file middleware, or layout markup—not the artwork. An ASP.NET Core favicon commonly fails because an asset sits outside the static root or the active Razor view never emits icon links.</p>\n\n<p>You do not need an ASP.NET Core-specific icon generator. Browsers read ordinary HTML, so the job is to prepare a small set of image files, serve them from <code>wwwroot</code>, and reference them from the shared layout. The <a href='https://html.spec.whatwg.org/multipage/links.html#rel-icon'>HTML standard</a> defines the external icon relationship through <code>rel='icon'</code>; ASP.NET Core simply needs to deliver that markup and its assets.</p>\n\n<h2>Prerequisites</h2>\n<ul>\n<li>An ASP.NET Core web project with a Razor, MVC, or plain HTML view you can edit.</li>\n<li>A square source logo or icon; vector artwork is useful, but a clean PNG also works.</li>\n<li>Permission to edit the shared layout and run the app locally.</li>\n<li>A browser with developer tools for verification.</li>\n</ul>\n<p>If the project has no <code>wwwroot</code> folder, create it at the project root, beside <code>Program.cs</code>.</p>\n\n<h2>Add an ASP.NET Core favicon in six steps</h2>\n\n<h3>1. Prepare the icon files</h3>\n<p>Prepare the artwork before touching the project. Aim for a mark that remains recognizable at 16 by 16 pixels, so remove unnecessary padding and favor one bold shape over fine text. <a href='/'>Mzu favicondl</a> can convert a source into the SVG, PNG, and ICO variants used below.</p>\n<p>For a practical browser stack, prepare:</p>\n<ul>\n<li><code>favicon.svg</code> for a scalable modern icon.</li>\n<li><code>favicon.ico</code> as a multi-size fallback, ideally containing 16, 32, and 48 pixel images.</li>\n<li><code>apple-touch-icon.png</code> as a practical 180 by 180 PNG for a home-screen shortcut.</li>\n</ul>\n\n<h3>2. Put the files in wwwroot</h3>\n<p>Place every asset in the project's <code>wwwroot</code> directory. Keep the names consistent with the later markup, because one mismatched filename produces a 404 even when the other icons work.</p>\n<pre><code>MyApp/\n├─ Program.cs\n└─ wwwroot/\n   ├─ favicon.svg\n   ├─ favicon.ico\n   └─ apple-touch-icon.png</code></pre>\n<p>In Razor views, prefer <code>~/favicon.svg</code> over <code>/favicon.svg</code>. In the minimal hosting model, the relevant part of <code>Program.cs</code> looks like this:</p>\n<pre><code>var builder = WebApplication.CreateBuilder(args);\nbuilder.Services.AddControllersWithViews();\n\nvar app = builder.Build();\n\napp.UseStaticFiles();\napp.UseRouting();\n\napp.MapControllerRoute(\n    name: \"default\",\n    pattern: \"{controller=Home}/{action=Index}/{id?}\");\napp.Run();</code></pre>\n<p>Do not add a second <code>app.UseStaticFiles()</code> call if the template already includes it.

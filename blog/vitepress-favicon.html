VitePress Favicon: Step-by-Step Setup Guide

If you've ever deployed a VitePress site and noticed the browser tab still shows the default VitePress logo, you're not alone. Many developers assume that placing a favicon.ico in the public folder is enough, but VitePress requires a bit more configuration to properly link your icon. This guide walks you through the exact steps to set a custom favicon for your VitePress site, from file placement to verifying the result.

Prerequisites

Before you start, make sure you have:

  • A VitePress project set up (version 1.x or later).
  • A favicon file ready. You can use an ICO, PNG, or SVG. If you need to create one, try Mzu favicondl to generate a multi-size favicon.
  • Basic familiarity with the config.js or config.ts file in your VitePress project.

Step 1: Place Your Favicon File in the Public Directory

VitePress uses Vite under the hood, so static assets should go into the public directory at the root of your project. Files in public are served at the root path and copied to the build output unchanged. For example, if you place favicon.ico in public, it will be accessible at /favicon.ico after building.

Create the public folder if it doesn't exist, and place your favicon file inside. You can also use a PNG or SVG file; just remember the filename.

your-project/
├── docs/
│   └── .vitepress/
│       └── config.js
├── public/
│   └── favicon.ico
└── package.json

Note: The public directory is relative to your VitePress project root (where package.json is). If you use the default structure with a docs folder, the public folder should be at the project root, not inside docs.

Step 2: Configure the Favicon in VitePress Config

VitePress allows you to define the <head> tags for your site via the head option in your config file. This is where you add the <link rel="icon"> tag.

Open your .vitepress/config.js (or .ts) and add the following:

import { defineConfig } from 'vitepress'

export default defineConfig({
  head: [
    ['link', { rel: 'icon', href: '/favicon.ico' }]
  ],
  // other config...
})

If you're using an SVG favicon, you can specify the type:

head: [
  ['link', { rel: 'icon', type: 'image/svg+xml', href: '/favicon.svg' }]
]

This tells VitePress to inject the link tag into the <head> of every page. The href should start with a slash (/) because the file is served from the root.

Step 3: Verify Your Favicon

After configuring, run your development server (npm run docs:dev or yarn docs:dev) and open your site in a browser. Check the tab—your favicon should appear. If it doesn't, try a hard refresh (Ctrl+F5 or Cmd+Shift+R) to bypass cache.

For production, build your site (npm run docs:build) and inspect the generated HTML in .vitepress/dist. Look for your <link rel="icon"> tag in the <head> section.

Common Pitfalls

  • Incorrect file path: If you place the favicon in docs/public instead of the project root public, it won't be copied. Always use the root public directory.
  • Missing leading slash: Using href: 'favicon.ico' (without slash) can cause issues on nested routes. Always use /favicon.ico.
  • Browser caching: Browsers aggressively cache favicons. After updating, clear your cache or use a different filename (e.g., favicon-v2.ico) to force a refresh. For more on cache issues, see our favicon not showing checklist.
  • SVG support: While SVG favicons are widely supported, some older browsers may not display them. Consider providing a PNG or ICO fallback. Learn more in our SVG favicon guide.

Conclusion

Setting a favicon in VitePress is straightforward once you know where to place the file and how to configure the head tags. By following these steps, you ensure your site has a professional look in browser tabs, bookmarks, and search results. Remember to test in different browsers and clear caches when making changes.

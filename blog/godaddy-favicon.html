GoDaddy Website Builder Favicon: A Step-by-Step Guide

If your GoDaddy site still shows the default icon in a browser tab, the replacement may be stuck in preview or the browser may be reusing an old icon. A GoDaddy Website Builder favicon is a site-wide browser icon, not an image placed inside a page section. Upload it in the editor, publish the site, then verify what the live HTML serves.

Prerequisites

You need edit and publish access to the GoDaddy site, plus a square source image. PNG is a practical upload format; a 512×512 px source gives you room to simplify the artwork before export. Keep the mark recognizable at 16×16 px, because thin strokes and detailed text usually disappear.

  • Your GoDaddy login and access to the Website Builder site
  • A square PNG or SVG source with a clear background
  • The live domain URL and a browser with Developer Tools

You can prepare the final PNG, ICO, and SVG variants with Mzu favicondl. The native uploader is the simplest route; the extra formats are useful only if you need a manual fallback.

Add a GoDaddy Website Builder Favicon Step by Step

1. Open the site in Website Builder

Sign in to GoDaddy, open Websites and Shop, and select the domain connected to your Website Builder site. Choose Edit Website to enter the editor. If the editor is already open, continue at the next step.

2. Open the favicon setting

Open the editor's site-wide settings panel and look for Favicon. Depending on the current editor layout, the control may appear under Settings or appear as Website icon. Choose the site-level control, not an image block inside a section or the regular logo field.

3. Prepare and select the image

Select Upload, Replace, or Select image, depending on the button shown. Choose your square PNG and crop it so the mark fills the frame without stretching. Leave a little space around the symbol instead of scaling the full logo edge to edge.

Preview the result at actual browser-tab size. If the artwork is too detailed, return to the source file and simplify it; enlarging a tiny raster image will only make the blur more obvious.

4. Apply the favicon

Confirm the preview and select Apply, Save, or the equivalent confirmation button. Check that the editor preview now shows your symbol. Some editor versions update the preview immediately, while others show the change only after publication.

5. Publish the change

Select Publish in the editor's top toolbar, then wait for the publishing confirmation. Open the live domain—not the editor canvas—in a new tab. An unpublished change can look correct in the editor while visitors still receive the previous site files.

6. Verify the live icon request

Open the live page source and inspect the document's <head> for an icon link. The HTML specification for rel='icon' defines this link relationship for an icon representing the page. A native result may look like this:

<link rel='icon' href='/favicon.ico'>

In browser Developer Tools, open the Network panel, reload the live page, and look for the icon request. Confirm that it returns a successful response and points to the file you uploaded. If the live HTML has no icon link, return to step 2 instead of adding a duplicate tag.

7. Use a manual fallback only when needed

If the native control cannot accept your preferred ICO or SVG, add a fallback only if your editor exposes a custom HTML or document-head field. Upload each file to a stable public URL, then reference those exact URLs in the head. Do not assume that a path such as /favicon.ico exists until you have uploaded it there.

<link rel='icon' href='/favicon.ico'>
<link rel='icon' type='image/png' sizes='32x32' href='/favicon-32x32.png'>
<link rel='icon' type='image/svg+xml' href='/favicon.svg'>
<link rel='apple-touch-icon' sizes='180x180' href='/apple-touch-icon.png'>

Replace each sample path with a real published URL, and remove duplicate icon tags already generated by Website Builder. If your plan or editor provides no custom-head control, use the native uploader instead.

Common pitfalls

The preview changes but the live site does not

Publish the site and test its public URL. Browser-tab symbols may remain cached, so use a private window or the cache steps in How to Clear Favicon Cache before changing the image again.

The browser requests a missing file

Compare the icon URL in the live <head> with the Network panel. A 404 usually means the file was uploaded to a different path, the URL is stale, or manual markup refers to a location that does not exist. Follow the broader Favicon Not Showing checklist if the native tag is present but no icon appears.

The icon is cropped, stretched, or invisible

Upload a square source image and keep the symbol inside the central safe area. If transparency makes the mark disappear against a tab background, export a version with a solid background and compare it at 16×16 px.

The tab still shows the old brand

Inspect the live markup before assuming GoDaddy failed to save. If it points to the new file, clear the favicon cache; if it points to the old file, republish and check that no stale template or duplicate icon link is overriding the upload.

Finish with a live-page check

Your setup is complete when the published page contains a successful icon request and the browser tab shows the intended mark. Repeat the check on a second browser or device because caches and icon-selection behavior can differ. That gives you a repeatable process for every future GoDaddy rebrand.

Flutter Web Favicon Setup: A Step-by-Step Guide for Apps

If your Flutter Web app still shows the default Flutter mark in a browser tab, the fix usually belongs in web/index.html, not in a Dart widget. A Flutter web favicon is a static image that the browser requests separately from your application UI.

You will link that image from Flutter’s web shell, keep web-app manifest images separate, then rebuild the static output. No Dart changes are required.

Prerequisites

  • Confirm that Web is enabled and your Flutter SDK can target Chrome. Run flutter doctor before changing assets.
  • Prepare a square source image with a simple silhouette. Tiny detail tends to disappear at tab size; review the favicon size guide before exporting.
  • Know the deployment base path: root, or a subdirectory such as /portal/. It affects how relative icon URLs resolve.

Add a Flutter web favicon in six steps

  1. Inspect Flutter’s web entry file

    Open web/index.html and search for rel='icon'. Flutter’s template may already contain a default icon link, so replace that reference instead of leaving two competing stacks.

    Open web/manifest.json too. Its icons array supplies installed web-app images, but it does not replace the browser-tab link you will add next.

  2. Prepare the static icon files

    Create a square icon set with Mzu favicondl. Export an SVG, 16- and 32-pixel PNGs, a multi-size ICO, a 180-pixel Apple touch image, and 192- and 512-pixel PNGs for the manifest.

    Place the files under web/icons/ so Flutter copies them with the rest of the static web assets:

    web/
├── index.html
├── manifest.json
└── icons/
    ├── favicon.svg
    ├── favicon-16.png
    ├── favicon-32.png
    ├── favicon.ico
    ├── apple-touch-icon.png
    ├── icon-192.png
    └── icon-512.png

  3. Add the icon links to the HTML head

    The HTML standard associates an icon resource with rel='icon'. Add one deliberate stack inside the <head> element of web/index.html:

    <link rel='icon' type='image/svg+xml' href='icons/favicon.svg'>
<link rel='icon' type='image/png' sizes='32x32' href='icons/favicon-32.png'>
<link rel='icon' type='image/png' sizes='16x16' href='icons/favicon-16.png'>
<link rel='icon' href='icons/favicon.ico'>
<link rel='apple-touch-icon' href='icons/apple-touch-icon.png'>

    Remove the template’s old icon links, then keep the Apple touch entry separate because it targets a different placement surface.

  4. Update the web-app manifest

    For a Flutter web app installed as a PWA, confirm that web/index.html contains <link rel='manifest' href='manifest.json'>. Add that link inside the head if it is missing, then update the existing icons array in web/manifest.json. Keep the manifest’s other keys unchanged.

    [
  {
    "src": "icons/icon-192.png",
    "sizes": "192x192",
    "type": "image/png"
  },
  {
    "src": "icons/icon-512.png",
    "sizes": "512x512",
    "type": "image/png"
  }
]

    These files support installed-app surfaces; they do not replace the explicit rel='icon' links in the HTML shell.

  5. Build and inspect the production output

    Build the production site:

    flutter build web --release

    Inspect build/web/index.html and build/web/icons/. The built index should contain your new links, and every referenced file should be present.

    If the app is served from a subdirectory, build with the same base path your host expects:

    flutter build web --release --base-href=/portal/

    Relative paths such as icons/favicon.svg then resolve against that generated base URL.

  6. Verify the request in browser developer tools

    Serve the production output locally:

    python3 -m http.server 8000 --directory build/web

    Open http://localhost:8000. In browser developer tools, confirm the links are in the document head. In the Network panel, filter for favicon, disable the cache, reload, and verify that the icon request returns 200.

    Repeat the request check on the deployed HTTPS URL, because the local folder can be correct while the host uses a different base path or blocks the asset.

Common pitfalls

  • Editing the wrong file: Change web/index.html, not build/web/index.html; the next build replaces generated output.
  • Using Flutter assets for the link: A bundled asset is not a public URL in the HTML head. Put favicon files in web/.
  • Leaving duplicate links: Search for every rel='icon' entry, including plugin-generated tags, and keep one intentional stack.
  • Ignoring the base path: If /portal/icons/favicon.svg returns 404, correct the Flutter base path or hosting rewrite before changing the icon.
  • Updating only the manifest: Manifest entries do not guarantee a browser-tab icon. Update the HTML links as well.
  • Judging by a cached tab: Rename the changed file or version its URL, then follow the broader favicon troubleshooting checklist.

Conclusion

A Flutter web favicon is ready when the source files live in web/, the HTML contains one clean icon stack, manifest paths match the same assets, and the production build serves every referenced file. That structure keeps the browser tab icon separate from Dart rendering while giving your deployment a predictable URL for each icon.

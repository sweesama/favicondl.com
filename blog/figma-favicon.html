Figma Favicon: How to Export and Add It to Your Site

If your brand is designed in Figma but your browser tab still shows a generic page icon, the missing piece is usually export and publishing. A Figma favicon starts as a square frame, but a browser needs finished files and HTML links. This workflow takes you from the canvas to a deployed icon.

Prerequisites

  • Access to the Figma editor and the file containing your brand assets.
  • A logo, symbol, or other mark that you can adapt for small sizes.
  • Your exported PNG or SVG file.
  • Access to the folder or build pipeline that publishes your site's static assets.

Create and export a Figma favicon

  1. 1. Build a square master frame

    Use Figma's Frame tool, click the canvas, and set both Width and Height to 512. Rename the frame Favicon / Master, then place the simplified brand mark inside it with a small margin. Designing large and scaling down later gives you more control than starting at tab size.

    For a wordmark, duplicate just the initial or symbol instead of shrinking the complete horizontal logo. At high zoom, inspect the smallest counters and stroke joins. Figma's pixel grid can reveal whether a gap will survive at 16 × 16 px, so simplify fine details before exporting.

  2. 2. Package the artwork as a component

    Create a component from the finished frame, then group layers under clear names such as Icon/Background and Icon/Mark. If you need light and dark versions, create component variants with identical geometry. Exporting controlled variants prevents small manual edits from producing inconsistent favicons.

  3. 3. Export PNG and SVG masters

    Select the master frame and open Export in Figma's right sidebar. Add a PNG export, keep it at 1×, and export the 512 px image. Add an SVG export as well. The PNG provides a raster source, while the SVG preserves vector geometry for browsers that support it.

    After exporting, open the PNG in a separate viewer and confirm that the canvas is square, the mark is centered, and the background is the intended color. This catches an accidentally selected group or unwanted transparent margin before conversion.

  4. 4. Generate the smaller formats

    Use Mzu favicondl to convert the PNG or SVG into a multi-size favicon.ico and the PNG sizes your site needs. Keep the original SVG instead of uploading a renamed PNG with an .ico extension. The favicon size guide explains where the 16, 32, 48, 180, 192, and 512 px files are used.

  5. 5. Add the icon links to your HTML

    Paste the following into the document <head>, adjusting the paths if your assets live elsewhere:

    <link rel='icon' href='/favicon.ico' sizes='any'>
<link rel='icon' href='/favicon.svg' type='image/svg+xml'>
<link rel='icon' href='/favicon-32.png' type='image/png' sizes='32x32'>
<link rel='icon' href='/favicon-192.png' type='image/png' sizes='192x192'>
<link rel='apple-touch-icon' href='/apple-touch-icon.png' sizes='180x180'>

    The HTML Living Standard defines rel='icon' links for declaring icon resources. Keep each path synchronized with the filename published on your server.

  6. 6. Publish the files at matching paths

    Put the files in the directory your site actually serves. A root deployment can use this structure:

    /
├── favicon.ico
├── favicon.svg
├── favavicon-32.png
├── favicon-192.png
└── apple-touch-icon.png

    In a bundled project, that location may be public/, static/, or another configured asset folder. Copy the files into the build output too if your deployment pipeline does not process that folder automatically.

  7. 7. Verify the live response

    For a static preview, run python3 -m http.server 8000 from the folder containing index.html, then open http://localhost:8000. This checks the same HTTP path your server will use and avoids file URL behavior.

    Open DevTools, select Network, and filter for favicon. Confirm that each requested file returns a successful response and opens as an image. Check the browser tab, a bookmark, and a newly opened tab rather than relying on one cached view. If the icon is missing or stale, use the favicon troubleshooting checklist before changing the design.

Common pitfalls

  • Exporting the full logo. A favicon needs one recognizable mark, not a wordmark or complete horizontal logo.
  • Using fine detail. Hairlines, tiny text, and low-contrast colors disappear at 16 × 16 pixels. Simplify the master rather than sharpening a raster export.
  • Mixing formats and names. A PNG with an .ico suffix is still a PNG. Generate the ICO container instead of renaming it.
  • Publishing to the wrong folder. A file in a source directory may never be copied into the deployed site. Test the final public URL.
  • Relying on SVG alone. Keep ICO or PNG fallbacks for environments that cannot render the SVG.
  • Ignoring the mobile icon. The Apple touch icon is a separate asset; exporting a desktop tab image does not create it.

Conclusion

Your Figma file now has a clear path to production: design a square component, export PNG and SVG masters, generate the fallback formats, publish them, and declare them in the page head. Keep the source component editable so future brand changes start from one controlled asset.

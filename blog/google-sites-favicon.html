Google Sites Favicon: Add and Verify It Step by Step

If your Google Sites favicon still appears as a generic globe or page icon in browser tabs, the upload probably reached only the draft—or the live site is serving a different icon URL. You can fix this without editing theme XML.

This step-by-step guide shows how to add a Google Sites favicon, publish it, and verify both the browser icon and its eligibility for Google Search. The browser check and the Search check are separate: one can work while the other waits for a recrawl.

Prepare the icon and site access

Open Google Sites in a browser where you can edit and publish the site. Before starting, prepare a square image with your logo mark, monogram, or symbol; a full wordmark usually becomes unreadable at 16×16 pixels.

  • Access: edit and publish rights for the site.
  • Source image: a square PNG is the simplest upload candidate. For a practical source, use a 192×192 PNG with a simple central mark.
  • Published URL: the sites.google.com address or custom domain where visitors will see the icon.

Google documents that a Search favicon must be square and at least 8×8 pixels; it recommends one larger than 48×48. A favicon is eligible for display, not guaranteed to appear, and its URL should remain stable. See Google's favicon documentation.

If your artwork is SVG, JPG, or another format, convert it to a square PNG before uploading. Mzu favicondl can handle that conversion; simplify the artwork before export so the browser-tab version keeps its silhouette.

Add a Google Sites favicon without custom code

  1. Open the site settings.

    Open your Google Sites dashboard, select the site, and click Edit. In the editor's top-right More or three-dot menu beside Publish, choose Site settings. Find the Favicon control and open its file picker.

  2. Upload and confirm the image.

    Select your prepared PNG. Check the preview or crop so the complete mark remains centered and visible, then save the selection. Keep enough solid color contrast that the icon does not disappear against a dark browser tab.

  3. Publish the updated site.

    Click Publish, confirm the site URL, and publish the update. Saving the image in Site settings does not change the visitor-facing site until the new version is published.

  4. Inspect the live homepage.

    Open the published URL in a new tab, not the editor preview. In browser developer tools, inspect the document head for an icon link. Then run this snippet in the DevTools console:

    Array.from(document.querySelectorAll('link[rel~=icon]')).map(function (link) {
  return {
    href: link.href,
    type: link.type,
    sizes: link.getAttribute('sizes') || ''
  };
})

    The result should include at least one favicon URL. The HTML standard defines rel='icon' as an external resource link for an icon, so inspect the link's actual URL rather than assuming it ends in favicon.ico.

    In the Network panel, reload the page and select the icon request. It should return an image response rather than an HTML fallback or a 404 response.

  5. Test the browser result.

    Reload the published page and check the tab, bookmarks, and shortcut. If an old icon remains, verify that the console shows the new asset URL, then try a private window; browsers can cache favicons separately from normal page content.

  6. Allow Google Search to recrawl.

    Use Google's Search favicon requirements to check the square shape, minimum size, stable URL, and crawl access. After publication, recrawling can take several days to several weeks, so an immediate Search result is not proof that the upload failed.

    For a focused diagnosis of a missing icon in results, see the Google Search favicon checklist.

Common Google Sites favicon pitfalls

  • Checking the editor instead of the live domain: Confirm that the published homepage contains the favicon rather than checking only the editing preview.
  • Changing the asset repeatedly: Each replacement may create a new icon URL. Keep the published URL stable after Google discovers it.
  • Using a detailed logo: Fine lines and small text disappear in a 16×16 tab. Test the mark at that size before publishing.
  • Confusing cache issues with Search delay: A browser can show the new icon while Google Search still shows the old one, or the reverse, because the two update paths differ.
  • Adding competing icon tags: With the native Google Sites uploader, avoid unnecessary HTML embeds that introduce multiple rel='icon' candidates and make troubleshooting harder.

Confirm the final setup

The reliable sequence is simple: upload one square PNG in Site settings, publish, inspect the live homepage, then let Google Search recrawl. If you manage a different no-code platform too, compare the process with the broader no-code website favicon guide.

Keep the published icon URL unchanged and check the canonical homepage again if the brand asset changes. That gives browser users, bookmark clients, and Google's crawler one consistent source to reference.

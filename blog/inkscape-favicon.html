Inkscape Favicon: Export a Crisp Icon for Your Site

If your Inkscape artwork looks fine on the canvas but becomes a clipped blur in a browser tab, the problem is usually the document, not the export format. An Inkscape favicon needs a square drawing, portable paths, and a small set of web-ready files.

Prerequisites

You need Inkscape and an existing SVG logo. If the artwork sits on a wide page, create a new square document, copy and scale the mark proportionally, and keep that file as the editable master. A recognizable symbol will work better at 16×16 pixels than a full wordmark.

For example, if the source is a 1200×400 wordmark, do not squeeze that rectangle into the favicon. Select the symbol alone, paste it into the square document, and scale it proportionally. This creates a compact master you can export repeatedly without altering the original artwork.

  • Use a 128×128-pixel artboard as a practical design size.
  • Keep the mark centered, with a little transparent space around it.
  • Remove details that cannot remain distinct at small sizes.

1. Set a square canvas and viewBox

Open File → Document Properties, set the units to pixels, and give the document equal width and height. The 128×128 size is a recommendation, not a browser requirement; 64×64 also works. For a 128×128 document, confirm that the viewBox reads 0 0 128 128.

Use Object → Align and Distribute, choose Page as the reference, and center the artwork horizontally and vertically. Confirm that the page preview is square and no edges are clipped.

2. Turn text and fragile effects into paths

Select each text object and choose Path → Object to Path. This prevents a server without your font from substituting a different shape.

Use Path → Stroke to Path for essential dashed or outlined strokes. Leave gradients, masks, and filters only when necessary, because they add failure points when the SVG is served in different environments.

3. Save a portable SVG

Choose File → Save As, select Plain SVG, and save the copy as favicon.svg.

Before converting the SVG, check that the document properties contain a square viewBox and that the artwork does not depend on an external font, linked bitmap, or stylesheet. If the logo contains a linked image, place it beside the SVG and relink it deliberately, or replace it with a vector equivalent.

4. Export a 512×512 PNG fallback

Use File → Export PNG Image, choose the page as the export area, and set both dimensions to 512 pixels. Keep the background transparent, then export favicon-512.png.

This high-resolution PNG gives a converter enough pixels to build small raster sizes without asking the browser to enlarge a tiny source.

For repeatable exports, you can also run:

inkscape favicon.svg --export-type=png --export-area-page --export-width=512 --export-height=512 --export-filename=favicon-512.png

The command uses the square page bounds and writes a 512-pixel PNG to the current working directory.

5. Create an Inkscape favicon package

Open Mzu favicondl, upload favicon.svg or favicon-512.png, generate a multi-size ICO, and download it. We recommend an ICO containing 16×16, 32×32, and 48×48 images. Also request a 180×180 PNG named apple-touch-icon.png.

If you want the exact packaging process, see the SVG to ICO guide; the favicon size guide covers the additional PNG and Apple sizes.

The HTML Standard defines rel='icon' as a link to an external resource representing the page in the user interface. That definition does not make one file format mandatory, so we recommend SVG plus an ICO fallback for compatibility.

6. Deploy the files and HTML

Place favicon.ico, favicon.svg, and apple-touch-icon.png at paths your site can serve. Add the links inside <head>:

<link rel='icon' href='/favicon.ico'>
<link rel='icon' href='/favicon.svg' type='image/svg+xml'>
<link rel='apple-touch-icon' href='/apple-touch-icon.png' sizes='180x180'>

Use root-relative paths only when they match the deployment root. In an application served under a subpath, update the paths or make them relative. Keep the ICO as a fallback and the SVG as the scalable master.

7. Verify the live response

Open the site, use a hard reload, and inspect the Network panel for each icon URL. Confirm that the request returns 200 and an image response, not the site's HTML 404 page.

Open /favicon.svg directly to confirm that the SVG renders. If the old icon persists, first verify that the browser fetched the new URL before changing the deployment.

You can also inspect the ICO response from a terminal:

curl -I https://example.com/favicon.ico

Replace the URL with your own domain, and repeat the check for the SVG and PNG files.

Common pitfalls

  • Artwork is cropped. Export from a square page, not the original wide canvas.
  • Text changes shape. Convert text to paths before saving the final SVG.
  • Linked assets fail. Replace linked bitmaps with vector artwork or package them at a stable relative path, and remove external stylesheet dependencies.
  • The icon looks empty. Inspect it at 16×16 and simplify the silhouette, spacing, and contrast.
  • The old icon persists. Check the HTML source and Network panel before blaming the cache.
  • The icon looks stretched. Keep the viewBox square and export a square PNG; sizes does not resize artwork.

Build a repeatable workflow

You now have a repeatable Inkscape favicon workflow: one square vector master, outlined text, a portable SVG, a 512-pixel PNG, an ICO fallback, and explicit HTML links. Keep the master SVG unchanged so future exports stay consistent.
